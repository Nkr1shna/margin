# Margin evals

Retrieval, generation and efficiency evals for Margin's agent and RAG pipeline
(`docs/agent-rag-architecture.md` §3). There is no eval surface in the app: evals live
here, and read the service's trace rows from outside.

Two ways they run:

- **CI** (`cargo test -p margin-evals`): fakes and recorded fixtures only. No model API,
  no Hugging Face, no Core ML model, no running service. Gates compare against
  `baseline.json` with the thresholds in `gates.toml`.
- **By hand** (`margin-eval`, the opt-in runner): real models with the owner's keys from
  the service Mac's Keychain, the real EmbeddingGemma embedder, and its own database
  folder. It never opens the running service's database; it reads cost, latency and
  cache numbers from the service's traces over `GET /api/traces` (or an exported JSONL).

## What is here

| Path | What |
|---|---|
| `corpus/` | The fixture library (under 5 MB, all written for this corpus, CC0): six prose documents (Markdown, reST, HTML), three PDFs (`rc-circuits.pdf` with a text layer, `glacier-scan.pdf` a scanned page with no text layer, `lens-optics.pdf` a text page plus a figure), four images (two labelled diagrams, two drawn scenes with no text), and `folder/`, an attached-folder tree whose `.md`, `.pdf`, `.png` and extension-less `README` are on the allow-list while `src/main.rs`, `data/results.json`, `archive.zip`, `.hidden.md` and `credentials.txt` must stay invisible. |
| `corpus/sources/` | The text the PDFs are made from, page by page (pages separated by a `\f` line). Anchors in PDFs are checked against these. |
| `tools/make_corpus.swift` | Draws the PDFs and images from `corpus/sources` (`swift evals/tools/make_corpus.swift` from the repository root). Diagram labels live in it, and image anchors are checked against them. |
| `tools/golden_retrieval.py` | The 60 hand-written retrieval queries; `python3 evals/tools/golden_retrieval.py > evals/golden/retrieval.jsonl`. |
| `golden/retrieval.jsonl` | Retrieval queries: `{id, query, scope, relevant: [{document, page?, anchor?}], kind, generated_by}`, kinds `lexical`, `semantic`, `cross-modal`, `negative`. A hit is relevant when its text contains an anchor (whitespace-normalised, case-insensitive) or, with no anchor, when it is the anchored picture. Negatives have no relevant items; their metric is "nothing above threshold". The first 60 are hand-written; the rest are generated by `synth-questions` and graded for seriousness (rows under 2 are dropped; no human review). |
| `variants/*.toml` | Pipeline configurations, the same shape as `Settings.pipeline` (`margin_shared::pipeline::PipelineConfig`). `baseline` is the shipped default; `hybrid`, `dense` and `bm25` vary the retriever. |
| `gates.toml` | How far a change may move each metric before CI fails. |
| `prices.toml` | USD per million tokens by model id, for `cost_usd` on trace rows and cost reports. |

Not yet here (R1-evals and the owner's first run add them): `baseline.json`,
`recorded/embeddings.bin` (real EmbeddingGemma vectors of every corpus chunk and golden
query, f16, keyed by `embedder_version + sha256(prefix + text)`), `recorded/generations/`,
`golden/courses.jsonl`, `rubrics/`, `reports/`. The corpus has no audio clip yet: a clip
made with the Mac's system voices may not be redistributable, so one will be recorded
by the owner with a known transcript.

## Record, run, compare

```sh
# Once, and again whenever the chunker or the embedding prefix changes (a deliberate,
# visible step: RecordedEmbedder fails loudly on any text it hasn't seen).
cargo run -p margin-evals --bin margin-eval -- record-embeddings

# A suite with a variant, against the runner's own database.
cargo run -p margin-evals --bin margin-eval -- run --suite retrieval --variant baseline
cargo run -p margin-evals --bin margin-eval -- run --suite retrieval --variant bm25

# Per-metric deltas with paired bootstrap 95% intervals.
cargo run -p margin-evals --bin margin-eval -- compare <run-a> <run-b>

# Markdown + single-file HTML report under evals/reports/.
cargo run -p margin-evals --bin margin-eval -- report
```

`compare` refuses runs made with different embedder versions unless
`--allow-embedder-change` is passed, so a win is never a side effect of fresh vectors.
Commit the new `baseline.json` (and the report's summary table) with the change that
improves it.

## Metrics

`margin_evals::metrics`: recall@k, reciprocal rank / MRR, nDCG@k (binary, an item found
twice counts once) and graded nDCG, false positives on negatives, dedup rate, Cohen's κ
and quadratic-weighted κ for judge agreement. Each is a pure function with hand-worked
tests.
