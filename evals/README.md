# Margin evals

Retrieval, generation and efficiency evals for Margin's agent and RAG pipeline
(`docs/agent-rag-architecture.md` §3). There is no eval surface in the app: evals live
here, and read the service's trace rows from outside.

Two ways they run:

- **CI** (`cargo test -p margin-evals`): fakes and recorded fixtures only. No model API,
  no Hugging Face, no real embedding model, no running service. Gates compare against
  `baseline.json` with the thresholds in `gates.toml`.
- **By hand** (`margin-eval`, the opt-in runner): real models with the owner's keys from
  the service's secrets file, the real EmbeddingGemma embedder (ONNX), and its own database
  folder (`/var/lib/margin/evals`, or `--data`). It never opens the
  running service's database; it reads cost, latency and cache numbers from the
  service's traces over `GET /api/traces` (or an exported JSONL). It refuses to run when
  `CI` (or `MARGIN_EVAL_NO_LIVE`) is set.

## What is here

| Path | What |
|---|---|
| `corpus/` | The fixture library (under 5 MB, all written for this corpus, CC0): six prose documents (Markdown, reST, HTML), three PDFs (`rc-circuits.pdf` with a text layer, `glacier-scan.pdf` a scanned page with no text layer, `lens-optics.pdf` a text page plus a figure), four images (two labelled diagrams, two drawn scenes with no text), and `folder/`, an attached-folder tree whose `.md`, `.pdf`, `.png` and extension-less `README` are on the allow-list while `src/main.rs`, `data/results.json`, `archive.zip`, `.hidden.md` and `credentials.txt` must stay invisible. |
| `corpus/sources/` | The text the PDFs are made from, page by page (pages separated by a `\f` line). Anchors in PDFs are checked against these. |
| `tools/make_corpus.swift` | Draws the PDFs and images from `corpus/sources`. |
| `tools/golden_retrieval.py` | The 60 hand-written retrieval queries → `golden/retrieval.jsonl`. |
| `tools/golden_courses.py` | The 8 golden course requests and 10 agent tasks → `golden/courses.jsonl`, `golden/agent.jsonl`. |
| `golden/retrieval.jsonl` | Retrieval queries: `{id, query, scope, relevant: [{document, page?, anchor?}], kind, generated_by, seriousness?, grader?}`. A hit is relevant when it is of the item's document (and page) and its text contains the anchor (whitespace-normalised, case-insensitive) or, with no anchor, it is a picture. The first 60 are hand-written; `s…` rows are generated by `synth-questions` and kept only when graded ≥ 2. |
| `golden/synth-log.jsonl` | Every generated candidate with its checks and grade, kept or not: the evidence for question quality (no human review, owner Q8). |
| `golden/courses.jsonl`, `golden/agent.jsonl` | Course requests (prompt, documents, outline themes, must-cite documents per lesson) and chat questions for the agent suite (one has no answer in the corpus). |
| `variants/*.toml` | Pipeline configurations, the same shape as `Settings.pipeline`. `baseline` is the shipped default. |
| `gates.toml`, `prices.toml` | CI allowances; USD per million tokens by model. |
| `runner.toml` | The runner's endpoints, models per slot and provider, writing-model window. The service is `--service-url` (dev; prod is refused). |
| `recorded/extracted.json` | What pdfium/tesseract read from each PDF and image (CI replays it; OCR isn't reproduced byte for byte elsewhere). |
| `recorded/embeddings.bin` | Real EmbeddingGemma vectors of every corpus chunk, picture and golden query. Format: `margin_embed::fake::Recording` (the one the service's `RecordedEmbedder` reads; see `crates/evals/src/recorded.rs`). A miss is an error, never a made-up vector. |
| `recorded/generations/<prompt version>/<model>/` | Recorded lessons with the passages they were sent, for the citation gate and `judge`. |
| `baseline.json` | The committed retrieval baseline the CI gate compares against. |
| `reports/` | `margin-eval report` output (Markdown + one self-contained HTML page per run). |
| `recorded/reranks.jsonl`, `recorded/rewrites.jsonl` | R2: what the listwise reranker (`listwise-small`) and the query rewriter (`small-expand-v1`) answered on the small-tasks model, one record per search, keyed by `sha256(stage + params, prompt version, purpose, query [, candidate ids])`, with the call's time and cost. CI replays them under the real stage names; a search not recorded is an error, never a made-up answer. |
| `prompts.lock` | Every prompt's version and the hash of its constant block; the always-on `prompt_lock` test fails when a constant block changes under an unchanged version. |

The judge rubrics, the question-generation and seriousness-grading prompts and the
canary sets (10 trivial questions to reject, 5 serious ones to keep, 20 deliberately bad
lessons) are R1-ai's, in `margin_ai::evals`; the runner uses them through
`crates/evals/src/ai_judge.rs`.

## First run on the service (before R1 is called done)

```sh
cargo run -p margin-evals --bin margin-eval -- record-embeddings
cargo run -p margin-evals --bin margin-eval -- record-generations
cargo run -p margin-evals --bin margin-eval -- run --suite retrieval --variant baseline --write-baseline
git add evals/recorded evals/baseline.json   # then remove the `ignore` in crates/evals/tests/gates.rs
```

## Run, compare, report

```sh
margin-eval run --suite retrieval --variant bm25
margin-eval run --suite courses            # writes, records and judges every golden lesson
margin-eval run --suite agent              # Margin's agent loop with `search` over the corpus
margin-eval synth-questions --limit 20     # generate, check, grade, keep ≥ 2
margin-eval grade-questions                # every golden question through every grader: κ, canaries
margin-eval judge --against evals/recorded/generations/lesson-v3   # pairwise, both orders
margin-eval runs
margin-eval compare <run-a> <run-b>        # paired bootstrap 95 % intervals per metric
margin-eval compare <run-a> <run-b> --allow-provider-change   # e.g. OpenAI vs Claude writer
margin-eval export --kind model_call --from 2026-10-01T00:00:00Z --out traces.jsonl
margin-eval report <run> --traces traces.jsonl
```

`compare` refuses runs made with different embedder versions unless
`--allow-embedder-change` is passed, so a win is never a side effect of fresh vectors.
It likewise refuses runs whose models came from different providers (OpenAI, ChatGPT,
Claude) unless `--allow-provider-change` is passed, so a win is never a side effect of
switching providers; with the flag the comparison carries a warning that the deltas
include the provider's effect. Each run records its providers (`providers` on the run,
shown as "Provider" in its report): the courses writer (or the recorded generations'
writer), the agent's model, the question generator; a retrieval run has none. A run
recorded before providers were compares with a warning. ChatGPT is its own provider even
on model ids OpenAI also serves. Commit the new `baseline.json` (and the report's summary
table) with the change that improves it.

## Alerts and performance budgets

```sh
margin-eval alerts --service-url https://devmargin.krishnanelloore.com
margin-eval perf   --service-url https://devmargin.krishnanelloore.com
```

`alerts` prints the service's active alerts (`GET /api/alerts`) and the last day's
rises and clears (its `alert` trace rows). The service's alert job
(`crates/service/src/alerts.rs`, `docs/phase5-brief.md` D6) compares the last
`[alerts] window_minutes` of traces with `[alerts]` in `service.toml` every minute; each
rise and clear also goes to journald (`journalctl -u margin-service -p warning`), to the
count in the public `GET /api/version` (`alerts_active`, `alerts_since`) and, when
`[alerts] webhook_url` is set, as a JSON `POST` (the `AlertEvent` plus `environment` and
a `text` line). `report` adds an "Alerts" section from the `alert` rows it reads.

`perf` measures the service against `budgets.toml` (D8: the Linux prod guest's
targets) and prints each as met, missed, not measured or manual. It ingests the
corpus's text documents as agent `perf` documents (`perf/<path>`) and sends one back
unchanged, runs every `golden/retrieval.jsonl` query over `POST /api/context/search`
(timed end to end, and by the `retrieval` rows), runs the first `golden/agent.jsonl`
question as a chat turn (step overhead `duration_ms − provider_ms`, cached share from
step 2, the title's tokens) and asks for a one-lesson course, accepting its outline cut
to one lesson. It deletes what it made (documents, chat, topics) at the end; the trace
rows stay. **It calls the service's configured models, not fakes: one real agent turn
and one real lesson on the provider dev is set up with (their tokens are the cost), and
its `Scope::Library` searches read the library the token can read.** Run it against dev
by hand after a deploy that touches ingest, retrieval or the loop (the prod URL is
refused). Numbers are reported, never gated.

## Cost per provider

`margin-eval report --traces FILE` (or `--service`) adds an Efficiency section from the
service's `model_call` trace rows (`docs/agent-providers-brief.md` D14): one line per
route, provider and model (calls, input, cached %, cache writes, output, web searches,
cost, mean latency), the total, and a **Cost by provider** table. A row's own `cost_usd`
(priced by the service when it was written) wins; otherwise the row is priced from
`prices.toml` by the same rule as the service's `trace::cost_usd`: fresh input
(input − cached − cache writes), cached reads and cache writes at their own prices,
output, Haiku 5.5's long-context tier past its `over`, plus `web_search` per 1 000
searches. A model missing from the table counts as "unpriced", never a guess. ChatGPT
calls are plan-billed: their tokens count, their cost cell says "plan-billed". A row
with no `provider` (recorded before providers) takes the one `prices.toml` lists its
model under.

## The Claude prompt-prefix gate

`crates/evals/tests/gates.rs` (`claude_prefix`) drives the real `ClaudeClient` against a
fake Messages server that records every request body, and checks them with
`margin_evals::prefix` (D12): for one prompt version, `system[0]` is that version's
constant block byte for byte with `cache_control: {"type": "ephemeral"}`; `system[1]` is
the rest of the instructions (the variable part), unmarked, and left out when there is
none; a text call has exactly one breakpoint; the constant block is sent nowhere else.
It covers lessons, scenes, the planner and the reranker, each call on its route's model.
A change to a constant block bumps its `prompt_version`. The OpenAI counterpart is
R1's prefix-identity test in `crates/ai/tests/fake_responses.rs`.

## Reranking, query rewriting and prompt versions (R2)

The listwise rerank and the query rewriter run on the small-tasks model, so CI can't call
them: the owner records their answers once and CI replays them
(`docs/r2-brief.md` §6). Recording is an owner step with the model keys; nothing
becomes the default by being recorded.

```sh
margin-eval record-rewrites --variant rewrite-small   # one small call per golden query/lesson plan
margin-eval record-reranks  --variant rerank-small    # one small call per golden query/lesson plan, over its fused candidates
margin-eval record-embeddings                         # also embeds the recorded rewrites
git add evals/recorded/rewrites.jsonl evals/recorded/reranks.jsonl evals/recorded/embeddings-*.bin
margin-eval run --suite retrieval --variant rerank-small   # served from the recording
margin-eval compare <baseline run> <rerank-small run>
margin-eval prompts                                   # the catalog against prompts.lock
margin-eval prompts --write-lock                      # after bumping a changed prompt's version
```

A rerank is keyed by its candidates, which come from the recorded vectors, so for a
variant with both stages (`r2-full`) run `record-rewrites` and `record-embeddings`
before `record-reranks` (its rewritten queries then search with the vectors CI replays).
Answers already recorded are reused, never paid for twice; a run of a variant with a
small-model stage is served from the recording and calls the model only for searches
that weren't recorded (with no key it replays only, and a miss is an error).
`rerank-small` sets `params.purpose = "lesson"` on its reranker: the retrieval suite then
searches the golden questions as lessons do (its reranker leaves the agent tool alone),
else it searches as the agent tool. The courses suite searches as lessons, the agent
suite as the agent tool. A variant's recorded lessons go under
`recorded/generations/<prompt version>+<variant>/`, so they never overwrite the
baseline's.

The retrieval report's **Reranking** section gives the share of the top 10 places the
reranker changed (`rerank_moved_at_10`), its fallbacks (searches it applies to that kept
the fused order), `rerank_ms`/`rewrite_ms` p50/p95, query strings per search, and the
small route's cost per query (from the stages' trace rows, or the recording's when
replayed). CI's `r2_variants_on_the_recorded_small_calls` replays `rerank-small` and
`rewrite-small` against `[rerank]` in `gates.toml` (at most 60 % of the top 10 moved, no
fallbacks) and the tool-output size; until a recording is committed that variant is
skipped with a message saying so.

Every run records the prompt versions its model calls used (`prompt_versions`, shown in
its report). `compare` refuses runs that ran one prompt under two versions ("rerank-v1 →
rerank-v2") unless `--allow-prompt-change`; a job only one run has (the variant adds a
reranker) is what is being compared, noted as a warning.

## How quality is shown without human review

- Every judge and grader runs the canaries on every run; one failure marks the run
  invalid (the report and `runs` say so), and `synth-questions` refuses to generate with
  a grader that fails them.
- Each lesson is judged twice with its passages in opposite order (markers renumbered);
  the two passes give a κ per criterion, and with both providers' keys a second judge
  gives an inter-judge κ.
- The seriousness distribution of hand-written and generated questions, the drop rate,
  and the inter-grader κ are in every `grade-questions` report.
- Negatives are scored against a calibrated threshold (the 10th percentile of answerable
  queries' first-relevant cosine), so the false-positive rate means the same across
  embedders.

## Metrics

`margin_evals::metrics`: recall@k, reciprocal rank / MRR, nDCG@k (binary, an item found
twice counts once) and graded nDCG, false positives on negatives, dedup rate, Cohen's κ
and quadratic-weighted κ, nearest-rank percentiles, paired bootstrap intervals. Each is a
pure function with hand-worked tests.
