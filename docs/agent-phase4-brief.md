#### D1 settled: the `Dir` trait (contract between 4-core and 4a/4b/4c)

Doc comment, verbatim in `folders/mod.rs`:

> A folder this device holds, opened for one tool call and dropped after it. Paths are `/`-separated and relative to the root; `""` is the root. Callers pass paths that `margin_shared::relative_components` accepted (no absolute path, no `..`, no NUL, no hidden or secret component), so implementations don't check those again. They do refuse anything that would leave the root: a symbolic link (to a file or a folder, anywhere in the path) is never followed — `list` leaves it out, `stat`/`open` answer `DirError::Outside` — and, where the platform can canonicalise, a resolved path outside the canonical root is `Outside` too. Android's document trees have no links, so there it never happens. `list` returns entries in any order (the tools sort by name) and only files and folders (special files are left out); which files the model may see is the tools' business, not the `Dir`'s. `open` streams: a reader over the file, never the whole file in memory where the platform allows it. Every method may block; the tools run them on a blocking thread. A folder whose access was lost (the bookmark can't be resolved, the URI grant is gone, the path is gone, permission is denied) is `DirError::Revoked(message)` with the message the model and the Folders pane show, e.g. "Margin no longer has access to the folder “notes”; attach it again on the iPhone."

```rust
pub trait Dir {
    fn list(&self, rel: &str) -> Result<Vec<DirEntry>, DirError>;
    fn stat(&self, rel: &str) -> Result<DirEntry, DirError>;   // NotFound, Outside
    fn open(&self, rel: &str) -> Result<Box<dyn Read + '_>, DirError>; // IsADir, NotFound, Outside
}
```

`StdDir` (first commit) resolves `rel` component by component with `symlink_metadata`; a symlink at any step is `Outside`; a final `canonicalize` of the result, when it succeeds, must start with the canonical root. It is the implementation for macOS, Linux and (wrapped in the security scope) iOS.

#### D5a settled: the six folder tools as the model sees them (4-agent)

`FOLDER_TOOLS = ["list_files", "find_files", "search_text", "read_file", "read_pdf", "view_image"]`, all `ToolKind::Device` (concurrent, read-only; the tool row names the holding device), all refused with the `device::workspace` message when the workspace isn't the chat's, all absent from `tool_choice` when the chat has no workspace (`turn.rs` already keys on the const).

- `list_files {workspace_id, path}` — "List what is directly inside a folder of an attached folder: every subfolder, and the files the agent can read ({FOLDER_FILE_TYPES_TEXT}); other kinds of files and hidden files are never listed. Read-only." `device_output_text` renders a file as `notes/ch1.md  (2.1 KB, modified 2025-10-09)`, `paper.pdf  (2.1 MB, PDF, modified …)`, `figure.png  (340 KB, image)`.
- `find_files {workspace_id, path, pattern}` — "Find readable files anywhere under a folder whose path matches a glob (`*`, `**`, `?`, case-insensitive). Folders are walked whatever their name. Read-only."
- `search_text {workspace_id, query, path, pattern}` — "Search the text documents under a folder for lines containing some text; `path:line: text` per match. PDFs aren't searched by this: find them with `find_files` and read them with `read_pdf`. Read-only." When `pdf_files > 0` the output ends with "[N PDF files under this path weren't searched; use read_pdf.]"
- `read_file {workspace_id, path, start_line, max_lines}` — text documents only (a PDF or image → the device answers "“x” is a PDF; read it with read_pdf." / "“x” is an image; look at it with view_image."); unchanged otherwise.
- `read_pdf {workspace_id, path, first_page, max_pages}` — "Read the text of pages of a PDF in an attached folder (scanned pages are recognised). At most 10 pages per call; read long documents in parts. To look at a page's figures or layout, use view_image with the page number. Read-only." `first_page ≥ 1`, `max_pages` clamped to `1..=PDF_PAGES_PER_READ`. Output: `notes/paper.pdf, pages 3–5 of 12:\n--- page 3 ---\n<text>\n--- page 4 ---\n(no text on this page)\n…` cut at `READ_FILE_MAX_BYTES` on a page boundary when a page fits, else inside the page with the usual cut marker; a trailing `[Pages 6–12 not shown; read on from page 6.]`. Summary "Pages 3–5 of 12". Label "Reading pages 3–5 of “paper.pdf”".
- `view_image {workspace_id, path, page: Option<u32>}` — "Look at an image in an attached folder, or at one page of a PDF (give the page number). The picture is shown to you with this call's result. At most 8 pictures per answer. Read-only." Output text `Picture of notes/figure.png (1200×800 px)` / `Picture of page 4 of notes/paper.pdf (of 12)`, plus the picture (below). A PDF without `page` → error "Give a page number to look at a page of a PDF."; `page` on an image → ignored; past the last page → "“x” has N pages.". Summary "Showing “figure.png”" / "Showing page 4 of “paper.pdf”". Label the same.

The two new tools don't go to the device as such: their `run` calls `ctx.folders: Arc<dyn FolderReader>` (a new `ToolContext` field; `NoFolders` answers "Folders can't be read here." for the agent crate's own tests):

```rust
pub trait FolderReader: Send + Sync + 'static {
    /// Pages `first..first+count` of a PDF in `ws` (fetching the file through its
    /// device when the cache doesn't have it), their text and the page count.
    fn pdf_pages<'a>(&'a self, ctx: &'a ToolContext, ws: &'a Workspace, path: &'a str, first: u32, count: u32)
        -> BoxFuture<'a, Result<PdfText { total_pages: u32, pages: Vec<(u32, String)> }, String>>;
    /// The picture of an image, or of PDF page `page`, as the model is shown it.
    fn picture<'a>(&'a self, ctx: &'a ToolContext, ws: &'a Workspace, path: &'a str, page: Option<u32>)
        -> BoxFuture<'a, Result<FolderPicture { image: margin_ai::Image, width: u32, height: u32, total_pages: Option<u32> }, String>>;
}
```

`Err(String)` is the text the model gets (offline, timed out, revoked, too large, not a PDF…). The agent crate also exports `pub async fn fetch_file(ctx, ws, path, known) -> Result<FileStamp, String>` (a `DeviceCall { call: FetchFile, timeout: FETCH_FILE_TIMEOUT }` through `ctx.devices`, with the offline/timeout texts of `dispatch`), which the service's reader uses; `FETCH_FILE_TIMEOUT = 120 s` beside the other timeouts (an upload over a slow link).

**Pictures in tool outputs.** `ToolOutput.images: Vec<margin_ai::Image>` (default empty). `record` builds the model item with `function_call_output(call_id, output, &images)`: with no images the `output` string as today; with images, `output` is a content array `[{"type":"input_text","text":output}, {"type":"input_image","image_url":data_url,"detail":"auto"}, …]`, stored as the `ToolResult`'s only model item, so replay is byte-identical. The ai owner confirms against the current Responses API reference that `function_call_output.output` accepts input content arrays and adds the fake-server case; if it turns out not to, 4-agent instead stores two model items for the result — the text output, then `{"role":"user","content":[{"type":"input_text","text":"The picture from view_image (call <call_id>), as data:"}, input_image…]}` — and says so in the contract; nothing else in the design depends on which. Images don't count toward `TOOL_OUTPUT_MAX_BYTES`/`TURN_OUTPUT_MAX_BYTES` (text budgets) but toward `VIEW_IMAGES_PER_TURN` (8): the ninth `view_image` of a turn is refused without running ("This answer has already looked at 8 pictures; answer with what you've seen."). `ChatItemKind::ToolResult.output_bytes` stays the text's length; the tool row's expanded output shows the text and "1 picture shown to the model". Phase 5's trim of old outputs (`turn.rs` 1291) must replace a content array by its text plus "[picture no longer shown]" — noted in the contract, not built here.

Prompt (`prompt.rs`): the folder sentence says the agent reads "text documents, PDFs and images" in attached folders and nothing else.

#### D5b settled: the device tools against `Dir` (`folders/tools.rs`, 4-core)

`pub fn run(call: &DeviceToolCall, cancel: &AtomicBool, host: &impl UploadHost) -> DeviceToolResult`: looks the workspace up in the store (none → `Err("This device doesn't hold the folder with that id.")`; revoked → that message), `folders::open(handle)` (`Revoked(m)` → `store::mark_revoked` + `Err(m)`), then:

- **Paths**: `relative_components(path)` → `Err(PathError.to_string())`; joined with `/`. **Visibility**: a file is listed, found, searched or read only when `folder_file_type(name)` is `Some`; every folder is entered (no name list), hidden names excepted (`is_skipped_name`).
- **`list_files`**: `stat` must be a folder (`IsADir`/`NotADir` → "“x” is a file, not a folder."; `NotFound` → "There's no “x” in the folder."); entries sorted by name; folders as `kind: None`; files with their type; cut at `MAX_LISTED_ENTRIES`, `truncated`.
- **`find_files`**: `globset::GlobBuilder::new(pattern).case_insensitive(true).literal_separator(true)` (bad pattern → "The pattern isn't a valid glob: …"); depth-first walk from `path` in name order, matching the path relative to `path`, files only, visible types only; stops at `MAX_LISTED_ENTRIES` matches or `SEARCH_MAX_SECONDS` → `truncated`.
- **`search_text`**: same walk; `Text` files only; a `Pdf` met on the walk (matching `pattern` if given) counts in `pdf_files`; skips text files over `READ_FILE_MAX_BYTES_TOTAL`; per file: read the first `TEXT_SNIFF_BYTES`, a NUL byte or invalid UTF-8 (allowing a cut final char) → skip; whole-file read counts toward `SEARCH_MAX_BYTES`; match = `line.to_lowercase().contains(&query.to_lowercase())` (query trimmed, not empty → else "Give some text to search for."); `TextMatch.text` = the line cut to `MATCH_LINE_MAX_CHARS` chars; stop at `MAX_TEXT_MATCHES`, bytes or seconds → `truncated`.
- **`read_file`**: `stat` must be a file; type `Pdf`/`Image` → the redirect texts in D5a; size cap → "“x” is N MB; files over 2 MB aren't read."; sniff → "“x” isn't readable as text."; the whole file read (≤ 2 MB), `\r\n` → `\n`, `total_lines` counted; `start_line > total` → "“x” has N lines."; lines from `start_line`, at most `max_lines` and `READ_FILE_MAX_BYTES` of text (cut at a line boundary); `end_line` = last included.
- **`fetch_file`**: `stat` must be a file of type `Pdf` or `Image` (`Text` → "“x” is a text document; read it with read_file."; invisible → `NotFound` text); size > `FOLDER_FETCH_MAX_BYTES` → "“x” is N MB; files over 32 MB aren't read."; `stamp = { bytes, modified }`; `known == Some(stamp)` → `Fetched { stamp, uploaded: false }`; else `dir.open(rel)` → `host.upload(workspace_id, request_id, reader, stamp.bytes)` (D6) → `Fetched { stamp, uploaded: true }`, or the upload's error ("Couldn't send “x” to the service: <reason>"). The reader is streamed; the size is re-checked as bytes go (a file that grew past the stamp → error).
- **Cancel**: the walk and per-file loops check `cancel` and return early; an upload in progress stops when its request task is aborted (the body stream ends; the answer is discarded).
- **Tests** (temp dir, `StdDir`, a `FakeUploadHost` that records what it got): each rule above; a tree with `src/main.rs`, `data.json`, `archive.zip`, `build/notes.md`, `.hidden.md`, `credentials.txt`, `paper.pdf`, `photo.HEIC` lists exactly `build/`, `paper.pdf`, `photo.HEIC` at the root and `notes.md` under `build/`; `find_files **/*` finds `build/notes.md`, `paper.pdf`, `photo.HEIC`; `search_text` reports `pdf_files == 1`; `read_file` on the PDF and the image answers the redirect texts; the cap and truncation flags; the sniff on a UTF-16 `.txt`; CRLF; `start_line` past the end; a glob with `**`; cancel mid-walk; `fetch_file` unchanged / uploaded / too large / a text file; cancel mid-upload leaves the host's stream unfinished.

#### D7b settled: the folder cache and the upload route (4-S)

`state.folder_cache_dir(workspace_id)/<key>/` with `key = hex(sha256(path ‖ 0 ‖ bytes ‖ 0 ‖ modified))[..32]`, files `file`, `meta.json` (`{ path, stamp, total_pages: Option<u32>, last_used }`), `pages.json`, `page-N.png`, `page-N.jpg`, `view.jpg`. `state.folder_stage_dir()/<request_id>` holds an upload until its tool call takes it. - **iOS/iPadOS**: `startAccessingSecurityScopedResource` false, or resolution error → `Revoked("Margin no longer has access to the folder “x”; attach it again on <this device>.")`; reads inside the scope; coordinated reads (a file only in iCloud downloads first; a `.icloud` placeholder is hidden and so never listed; a 32 MB PDF in iCloud may take a while — the fetch timeout covers it or the model is told). Reads and uploads only while the app is in front (socket rule; phase 5 extends it).
- **Android**: the tree URI with a persisted read grant; `SecurityException` anywhere → `Revoked` (same text with "on <this device>"); `forget` releases the grant; the storage root, `Download` and `Android/data` can't be picked (SAF); `DirEntry.modified` from `COLUMN_LAST_MODIFIED`.
- Every platform's `pick_folder` returns `location` as the owner would recognise it (`~/Developer/margin`, `iCloud Drive/Notes`, `Internal storage/Documents`), display only.
- No platform parses a PDF or decodes an image; all three ship bytes. Uploads go to the service the device is signed in to, with the device token; no key or model call happens on a device.

#### D12 settled: what the model sees

The folder tools are in `tools` (one cache-prefix change at this release); `propose_course`/`write_lesson` describe `folder_files`; `read_file` output carries line numbers, `read_pdf` page markers; `view_image` results carry a picture. The device's `Revoked` message reaches the model as the tool error and the owner as the badge. Folder file names and contents are data (the prompt says so already); page text and OCR arrive as tool output, never in the developer message.

#### Review lenses

- **Path safety**: every path goes through `relative_components` before `Dir`; `StdDir` refuses symlinks at every component; nothing joins a model-given path to a root any other way; no `canonicalize`-only check stands alone; the service never opens a path from a tool argument — only cache and stage files it named itself.
- **Visibility**: every listing, walk, search, read and fetch filters with `folder_file_type`; no second list of extensions anywhere (grep for `"pdf"` outside `device.rs` and `media.rs`).
- **Blocking and cancellation**: no `Dir` call on the Dioxus thread or inside the live loop's `select!`; every walk checks `cancel`; a dropped request can't write a signal; a dropped reader future leaves nothing but a stage file the cleanup removes; `spawn_blocking` extraction is bounded by page count and timeout.
- **Handles stay local**: no handle, bookmark or URI in any request body, log line or event; `folders.json` is written atomically; `prune` only after a successful list.
- **Uploads are gated**: a `PUT` without a pending `FetchFile` from that device for that workspace is refused; sizes are checked from `Content-Length` before reading and against the stamp after; the stage dir is never served.
- **Lock rule** (service): spans read before `to_the_end`; the `folder_passages` row and the proposal under one `write_lock`; no sink call while holding it.
- **Budget and size**: `FOLDER_FILES_MAX`/`FOLDER_PICTURES_MAX`/`FOLDER_SPAN_MAX_LINES` enforced before any device call; `PDF_PAGES_PER_READ`, `VIEW_IMAGES_PER_TURN`, `FOLDER_FETCH_MAX_BYTES`, `FOLDER_CACHE_MAX_BYTES` each tested; excerpts capped; `GET /api/library` size checked with 12 file-cited lessons; the model never gets more than 1536 px JPEGs.
- **Every UI element works**: Attach (both entry points, both chat states), ✕ detach, Remove with confirm, the revoked and no-handle badges, the viewer's stored/live/offline states for all three kinds, Previous/Next across mixed citations, keyboard and touch (long-press menus unchanged).
- **Platform builds**: `cargo test -p margin-app` (desktop), `cargo check` for `aarch64-apple-ios-sim`, `dx build --platform android` succeeds on this machine; 4b verified in the simulator, 4c in the emulator.
- **Strings**: error texts name the device and what to do; no "desktop"; the model-facing texts are the ones in D5a/D5b/D8/D11 verbatim; the Folders pane and the menu say what is read and that PDFs/images go to the service.

### 4. Still open for the owner (with my recommendation)

1. **The exact allow-list.** Working default (D0): text documents `.md .markdown .txt .text .rst .adoc .org .tex .bib .html .htm` and the names `README`/`LICENSE`; PDFs; images `.png .jpg .jpeg .heic .heif .webp .gif .tif .tiff .bmp`. Left out on purpose: data and config (`.csv .tsv .json .yaml .yml .toml .xml .ini`), subtitles (`.srt .vtt`), build-tool names; code, audio and video are decided out (above). Office and e-book formats (`.docx .pptx .rtf .epub .pages .key`) are not readable by Margin today (no extractor) — say if you want them and they become a separate item. Recommend **the default as listed**.
2. **The per-file fetch cap**: 32 MB (one request; a bigger file is listed but "isn't read"). Matching the 50 MB source cap would need the parts upload. Recommend **32 MB**.
3. **The service-side cache** of PDF/image bytes a device shipped (1 GB LRU, deleted with the folder, said in the Folders pane). Recommend **yes**; the alternative is re-sending a PDF for every page read.
4. **Picture caps**: 8 pictures per answer (`view_image`), 4 PDF pages or images per lesson from folders (on top of 4 from sources). Recommend **as set**.
5. **`search_text` doesn't search PDFs** (it tells the model to `read_pdf` them). Searching cached PDF text is possible later. Recommend **as designed** for phase 4.
