#### D1 settled: the `Dir` trait (contract between 4-core and 4a/4b/4c)

Doc comment, verbatim in `folders/mod.rs`:

> A folder this device holds, opened for one sync and dropped after it. Paths are `/`-separated and relative to the root; `""` is the root. The sync walks every folder (hidden names excepted) and takes only files `margin_shared::folder_file_type` knows; a `Dir` doesn't filter. It does refuse anything that would leave the root: a symbolic link (to a file or a folder, anywhere in the path) is never followed — `list` leaves it out, `stat`/`open` answer `DirError::Outside` — and, where the platform can canonicalise, a resolved path outside the canonical root is `Outside` too. Android's document trees have no links, so there it never happens. `list` returns entries in any order (the sync sorts by name) and only files and folders (special files are left out), each with its size and modification time when the platform gives one. `open` streams where the platform allows it. Every method may block; the sync runs them on a blocking thread. A folder whose access was lost (the bookmark can't be resolved, the URI grant is gone, the path is gone, permission is denied) is `DirError::Revoked(message)` with the message the Folders pane shows, e.g. "Margin no longer has access to the folder “notes”; attach it again on the iPhone."

```rust
pub trait Dir {
    fn list(&self, rel: &str) -> Result<Vec<DirEntry>, DirError>;
    fn stat(&self, rel: &str) -> Result<DirEntry, DirError>;   // NotFound, Outside
    fn open(&self, rel: &str) -> Result<Box<dyn Read + '_>, DirError>; // IsADir, NotFound, Outside
}
```

`StdDir` resolves `rel` component by component with `symlink_metadata`; a symlink at any step is `Outside`; a final `canonicalize`, when it succeeds, must start with the canonical root. It is the implementation for macOS, Linux and (wrapped in the security scope) iOS.

#### D6 settled: the sync engine (`folders/sync.rs`, 4-core)

One `sync::run(ws_id)` per workspace at a time (a second request while one runs is coalesced into "run again when done"). Steps:
1. **Scan** (blocking thread): `folders::open(handle)` (`Revoked(m)` → `store::mark_revoked`, state `Failed(m)`, stop); depth-first walk from the root through `Dir::list`, name order, skipping `is_skipped_name` entries and anything `folder_file_type` doesn't know; `ManifestFile { path, bytes, modified }` per file. Caps: none on count or bytes (owner); the walk checks the cancel flag.
2. **Manifest**: `api.sync_workspace(ws_id, SyncManifest)` → `SyncPlan { upload, kept, removed }` (D7a). `store::touch_synced`.
3. **Upload**, in `plan.upload` order, through the app's existing upload queue (`AppCtx.uploads`, `Upload::to(candidate, Destination::Folder(ws_id))` — a new `Destination` variant; `Upload.folder` = the folder's name): files ≤ `UPLOAD_PART_BYTES` in one `POST /api/sources?name=<path>&workspace_id&modified`, larger ones through `SOURCE_UPLOADS` in parts with `workspace_id&modified`, each part's bytes read through `Dir::open` on a blocking thread into the request body (the `Dir` is reopened per file, so a long sync on iOS holds the scope only while reading). A file that vanished or changed between scan and upload is skipped (the next sync catches it). Each finished upload pushes `WorkspaceChanged` through the socket (the service's `sync` counts), so the pane and strip move.
4. **Done**: state `Idle { last: now }`, or `Failed(message)` with the first upload error (the rest still tried).

State: `AppCtx.folder_sync: Signal<BTreeMap<Id, SyncState { Scanning | Uploading { done, total, bytes_done, bytes_total } | Idle { last } | Paused | Failed(String) }>>`. Triggers: attach; launch, for every held folder, once the socket is live; the socket (re)connecting; `foreground` turning true on mobile; every `FOLDER_SYNC_INTERVAL_SECS` while live; "Sync now" in the pane; a `SyncFolder` request (`Host::folder` runs steps 1–2, answers the `Done` message with the plan's counts, and lets step 3 go on in the background). **Pause**: on iOS/Android, `foreground` turning false aborts the running upload request and sets `Paused` ("Paused — open Margin to continue"); the next foreground resumes from the manifest (parts uploads continue from `GET source_upload(id).received`, which the upload queue already does). Detach-by-removal (D10) cancels the sync and drops the folder's queued uploads. Deletions and renames are the service's business from the manifest (a rename is a removal plus an upload; D7a). Tests (temp dir, `StdDir`, a fake `Api`): the manifest lists exactly the allow-listed files with stamps (the D5b tree: `build/notes.md`, `paper.pdf`, `photo.HEIC`; not `src/main.rs`, `data.json`, `.hidden.md`, `credentials.txt`); the plan's `upload` paths are uploaded in order with `workspace_id` and `modified`; a > 32 MB file goes in parts; cancel mid-scan and mid-upload; `Revoked` marks the store; coalescing.

`tools::Host` gains `fn folder(&self, call: DeviceToolCall) -> Pin<Box<dyn Future<Output = DeviceToolResult>>>` for `SyncFolder` (a workspace this device doesn't hold → `Err("This device doesn't hold the folder with that id.")`); `FOLDERS_NOT_YET` goes. Test: a `SyncFolder` request runs the fake sync and answers `Done`.

Built as briefed, with two changes from §2.7 of the RAG doc: the manifest carries a SHA-256 stamp per file (hashed on the device, streamed), and folder uploads bypass the composer's upload queue so a chat's files are never behind a folder's. The service side it talks to is D7a and D7a'.

#### D7a settled: folder files are sources (4-S, `sources.rs`, `uploads.rs`)

- **Upload queries.** `UploadQuery` and `StartQuery` gain `workspace_id: Option<Id>` and `modified: Option<DateTime<Utc>>` (the app sends `name=<path>&workspace_id&modified`, D6). `Upload` gains `workspace: Option<Workspace>` and `modified`. `Upload::check` takes the calling device (`sources::upload`, `uploads::start` gain `Extension(CurrentDevice(device))`): with `workspace_id`, the workspace must exist (404 "folder") and be that device's (403 `not_yours`, "This folder is attached on {device_name}; only that device sends its files."); `topic_id` must be absent (400 `bad_request`, "A folder's file can't be filed under a topic."); `folder_file_type(name)` must be `Some` (400 `unsupported_source`, "Margin doesn't take {name} from folders: only {FOLDER_FILE_TYPES_TEXT}."), and `kind = folder_file_type(name).source_kind()`; `name` must pass `relative_components` (400 `bad_path`, "{name} isn't a path inside the folder."); `folder` in the query is ignored and set to the workspace's name. `Upload::limit()` is `u64::MAX` for a folder file (owner: no cap; `UPLOAD_PART_BYTES` still bounds one request, and `routes::max_source_bytes` keeps applying to topic and chat files; `too_large_text` is never used for folder files).
- **Receiving computes the stamp.** `sources::receive` hashes what it writes (SHA-256, streamed) and returns `(bytes, sha256)`; `uploads::finish` hashes the assembled file once (streamed) before `create`. The hash is what the `folder_file` row records (D7a'), so the service never trusts the manifest's hash for what it holds.
- **Replacement in place.** `sources::create` becomes `create_or_replace`: under `write_lock`, a folder file whose `(workspace_id, name)` already has a source **keeps that source id** — the new `file` is moved over the old one's (`source_dir(old)/file`), the old `input.*` link and `source_media_dir(old)` are removed, `bytes`/`modified` updated, `status = Queued`, `created_at` kept — the just-written `source_dir(new_id)` is removed, `SourceChanged` is emitted and the id is queued. So a changed file re-embeds only its changed chunks (`ingest`'s hash diff, §2.7), keeps its `document_id` (old citations resolve to the new passages or, for a page that is gone, to the gone state), and bumps the document's generation. A new path gets a new id as today. Uploading the same path twice leaves one source; a topic or chat upload is unchanged.
- **Ingestion**: unchanged (`queue_source` → `source_document_locked` makes the `Origin::FolderFile` document, `ingest` writes passages with `scope_ids = [workspace_id]`). After a folder source is created, replaced, Ready or Failed, `folders::refresh_sync` runs (D7a'; `ingest`'s two status writes call it when the source has a `workspace_id`).
- **Queue**: `ingest::next_job` already takes any non-folder document before the next folder file; `sources::run_worker` and `enqueue_queued` need nothing. D13 tests it.

#### D7a' settled: the `folder_file` rows, the sync route, `Workspace.sync` (4-S, `folders.rs` new, `db.rs`)

`db::FOLDER_FILE = "folder_file"` (schemaless like the other tables, `{ doc }` records, listed with `list_where(.., "workspace_id", ..)`):

```rust
/// What the service knows about one path of a folder: the stamp the device last
/// reported, and the source it became once received.
pub struct FolderFileRow {
    pub id: Id,
    pub workspace_id: Id,
    pub path: String,
    pub kind: FolderFileType,
    /// The stamp the last manifest listed for the path.
    pub listed: FileStamp,
    /// The source holding the file, once received; its stamp is `received`.
    pub source_id: Option<Id>,
    pub received: Option<FileStamp>,
    pub listed_at: DateTime<Utc>,
}
```

A row is **current** when `received == Some(listed)` and the source exists; otherwise the device owes an upload (`Workspace.sync.uploading` counts these). The row is the folder's live view for `list_files`/`find_files` (D5a): received rows show the source's status, the rest "waiting to be sent".

- **`POST /api/workspaces/{id}/sync`** (`folders::sync`, `SyncManifest` → `SyncPlan`): 404 "folder"; 403 `not_yours` unless the calling device holds it ("Only the device holding this folder can sync it."); any path failing `relative_components` → 400 `bad_path`; entries whose `folder_file_type(path)` is `None` or doesn't match `kind` are ignored (the device filters first; this is the second line of defence). Under one `write_lock`: load the workspace's rows and sources; for each manifest entry, upsert its row with `listed = stamp` (`listed_at = now`), and classify it **kept** when the row is current, else **upload**; for each row whose path the manifest doesn't list, `sources::delete_locked` its source if any (`SourceDeleted`; passages, document and tombstone go with it) and delete the row: **removed**. A changed file is `upload`, not `removed`: its source stays searchable until the new copy lands and replaces it (D7a). `plan.upload` in path order, `kept`, `removed`; the workspace's `sync` is recomputed with `last_synced_at = now` and written; after the lock, `WorkspaceChanged` (and the `SourceDeleted`s) are emitted. Idempotent: the same manifest twice gives the same plan minus what arrived in between; once every upload landed, it gives `upload: []`. A rename is a removal plus an upload.
- **`GET /api/workspaces/{id}/files`** (`folders::files`): 404; any device may read; the workspace's sources, newest `created_at` first, through `public_source` (signed `media_url`). Rows not yet received aren't sources and aren't listed; the pane shows them as `sync.uploading`.
- **`Workspace.sync` upkeep** (`folders::refresh_sync(state, workspace_id)`): recomputes `files` (sources of the workspace), `bytes` (their `Source.bytes`: originals; renders and vectors aren't counted), `uploading` (rows not current), `reading` (sources Queued/Processing), `failed` (Failed), keeps `last_synced_at`; writes the `Workspace` row under `write_lock` and emits `WorkspaceChanged`, coalesced to at most one emit per 500 ms per workspace (`AppState.folder_sync_emits: Mutex<HashMap<Id, Instant>>` plus one deferred emit, like `Progress`). Called after a manifest, after `create_or_replace`, and from `ingest` on Ready/Failed. No sink call while holding the lock.
- **Deletion** of a workspace (D7d) deletes its rows with its sources. `server::recover` doesn't touch rows (a restart keeps pending ones; the next manifest fixes anything stale).
- **Not driven by the service**: `DeviceToolCall::Manifest` and `FetchFile` stay in the protocol and the app answers them, but 4-S sends neither (the device pushes; the agent's `sync_folder` is the only pull). See open question 3.

#### Review lenses

- **One index, one tool family**: `grep` for `search_folder`, `read_pdf`, `view_image`, `FolderIndex`, `search_text`, `read_file` in `crates/{agent,service}` finds nothing; `search` reaches folders through `Scope::Workspace`; `list_files`/`find_files` read `folder_file` and `source` rows and never a file on disk or a device.
- **Path safety**: every path from a device or the model goes through `relative_components`; the service opens only files it named itself (`source_dir(id)/file`); `globset` patterns are matched against stored paths only.
- **Visibility**: the manifest route and the upload route both filter with `folder_file_type`; no second extension list.
- **Stamps**: the service records the hash of what it received, never the manifest's; a row is current only when `received == listed`; the diff runs under one `write_lock` with the deletions; `refresh_sync` after the lock; no sink call inside it.
- **Replacement keeps ids**: re-uploading a path keeps its source and document id, removes the old renders and link, and queues an ingest whose diff keeps unchanged passages.
- **Scoping**: folder sources never in `Library.sources`, `list_sources`, `attach_sources`, a chat's `source_ids`, a topic, or the purge (`search_library` reads lessons and notes only, as today); `Scope::Workspace` bound to one workspace id.
- **Pictures**: `ToolOutput.images` only ever holds what `image_for_model` produced; the picture item follows its `function_call_output` in the same `model_items`; no size or count cap beyond `Budget.images_max` in packing; condensing strips old pictures; replay is byte-identical (the strict-schema and replay tests still pass).
- **Lock rule and budgets** (service): `insert_many` ≤ 64 rows; the manifest diff is one statement sequence under the lock; `MAX_LISTED_ENTRIES` and `RETRIEVAL_OUTPUT_MAX_BYTES` cap listings; `GET /api/library` size checked with a 1 000-file folder attached (it must not grow).
- **Strings**: every error names the device and what to do; the model-facing texts are D5a's verbatim in both crates; `list_sources`' description says folders are listed by `list_files`.
- **Builds**: `cargo test -p margin-agent -p margin-service`, then the whole workspace with 4-core's app tests, the iOS check and `dx build --platform android` after the integrator merges both areas.
