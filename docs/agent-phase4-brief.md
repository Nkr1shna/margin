#### D1 settled: the `Dir` trait (contract between 4-core and 4a/4b/4c)

Doc comment, verbatim in `folders/mod.rs`:

> A folder this device holds, opened for one tool call and dropped after it. Paths are `/`-separated and relative to the root; `""` is the root. Callers pass paths that `margin_shared::relative_components` accepted (no absolute path, no `..`, no NUL, no hidden or secret component), so implementations don't check those again. They do refuse anything that would leave the root: a symbolic link (to a file or a folder, anywhere in the path) is never followed — `list` leaves it out, `stat`/`open` answer `DirError::Outside` — and, where the platform can canonicalise, a resolved path outside the canonical root is `Outside` too. Android's document trees have no links, so there it never happens. `list` returns entries in any order (the tools sort by name) and only files and folders (special files are left out). Every method may block; the tools run them on a blocking thread. A folder whose access was lost (the bookmark can't be resolved, the URI grant is gone, the path is gone, permission is denied) is `DirError::Revoked(message)` with the message the model and the Folders pane show, e.g. "Margin no longer has access to the folder “notes”; attach it again on the iPhone."

```rust
pub trait Dir {
    fn list(&self, rel: &str) -> Result<Vec<DirEntry>, DirError>;
    fn stat(&self, rel: &str) -> Result<DirEntry, DirError>;   // NotFound, Outside
    fn open(&self, rel: &str) -> Result<Box<dyn Read + '_>, DirError>; // IsADir, NotFound, Outside
}
```

`StdDir` (first commit) resolves `rel` component by component with `symlink_metadata`; a symlink at any step is `Outside`; a final `canonicalize` of the result, when it succeeds, must start with the canonical root. It is the implementation for macOS, Linux and (wrapped in the security scope) iOS.

#### D5 settled: the four tools against `Dir` (`folders/tools.rs`, 4-core)

`pub fn run(call: &DeviceToolCall, cancel: &AtomicBool) -> DeviceToolResult`: looks the workspace up in the store (none → `Err("This device doesn't hold the folder with that id.")`; revoked → that message), `folders::open(handle)` (`Revoked(m)` → `store::mark_revoked` + `Err(m)`), then:

- **Paths**: `relative_components(path)` → `Err(PathError.to_string())`; joined with `/`. Listing entries drop `is_skipped_name` names.
- **`list_files`**: `stat` must be a folder (`IsADir`/`NotADir` → "“x” is a file, not a folder."; `NotFound` → "There's no “x” in the folder."); entries sorted by name, `binary` by name (`SourceKind::for_name` is `Some(Pdf|Image|Audio|Video)`) or size > `READ_FILE_MAX_BYTES_TOTAL`; cut at `MAX_LISTED_ENTRIES`, `truncated`.
- **`find_files`**: `globset::GlobBuilder::new(pattern).case_insensitive(true).literal_separator(true)` (bad pattern → "The pattern isn't a valid glob: …"); depth-first walk from `path` in name order, skipping skipped names, matching the path relative to `path`; stops at `MAX_LISTED_ENTRIES` matches or `SEARCH_MAX_SECONDS` → `truncated`.
- **`search_text`**: same walk, files only, pattern optional; skips by-name binaries and files over `READ_FILE_MAX_BYTES_TOTAL`; per file: read the first `TEXT_SNIFF_BYTES`, a NUL byte or invalid UTF-8 (allowing a cut final char) → skip; whole-file read counts toward `SEARCH_MAX_BYTES`; match = `line.to_lowercase().contains(&query.to_lowercase())` (query trimmed, not empty → else "Give some text to search for."); `TextMatch.text` = the line cut to `MATCH_LINE_MAX_CHARS` chars; stop at `MAX_TEXT_MATCHES`, bytes or seconds → `truncated`.
- **`read_file`**: `stat` must be a file; size cap → "“x” is N MB; files over 2 MB aren't read."; sniff → "“x” is a binary file."; the whole file read (≤ 2 MB), `\r\n` → `\n`, `total_lines` counted; `start_line > total` → "“x” has N lines."; lines from `start_line`, at most `max_lines` and `READ_FILE_MAX_BYTES` of text (cut at a line boundary); `end_line` = last included.
- **Cancel**: the walk and per-file loops check `cancel` and return early (the answer is discarded).
- **Tests** (temp dir, `StdDir`): each rule above, including the hidden/secret/`node_modules` skips, the cap and truncation flags, the sniff on a PNG and on a UTF-16 file, CRLF, `start_line` past the end, a glob with `**`, cancel mid-walk.

#### Review lenses

- **Path safety**: every path goes through `relative_components` before `Dir`; `StdDir` refuses symlinks at every component; nothing joins a model-given path to a root any other way; no `canonicalize`-only check (TOCTOU) stands alone.
- **Blocking and cancellation**: no `Dir` call on the Dioxus thread or inside the live loop's `select!`; every walk checks `cancel`; a dropped request can't write a signal.
- **Handles stay local**: no handle, bookmark or URI in any request body, log line or event; `folders.json` is written atomically; `prune` only after a successful list.
- **Lock rule** (service): spans read before `to_the_end`; the `folder_passages` row and the proposal under one `write_lock`; no sink call while holding it.
- **Budget and size**: `FOLDER_FILES_MAX`/`FOLDER_SPAN_MAX_LINES` enforced before any device call; excerpts capped; `GET /api/library` size checked with 12 file-cited lessons.
- **Every UI element works**: Attach (both entry points, both chat states), ✕ detach, Remove with confirm, the revoked and no-handle badges, the viewer's load/offline/gone states, Previous/Next across mixed citations, keyboard and touch (long-press menus unchanged).
- **Platform builds**: `cargo test -p margin-app` (desktop), `cargo check` for `aarch64-apple-ios-sim`, `dx build --platform android` succeeds on this machine; 4b verified in the simulator, 4c in the emulator.
- **Strings**: error texts name the device and what to do; no "desktop"; the model-facing texts are the ones in D5/D8/D11 verbatim.

### 4. Questions for the owner (with my recommendation)

- **Q1 — Regenerating a lesson that cites folder files: stored spans, or re-read from the device?** Recommend **stored** (what the lesson was written from; works offline; deterministic). Re-reading would silently change citations when files changed and fail when the device is away. Phase 4 builds stored.
- **Q2 — The fixed skip list.** The tools never list hidden names, `node_modules`, `target`, `build`, `dist`, `__pycache__`, `venv`, `DerivedData`, `Pods`, or secret-looking files, anywhere in the tree, so a project whose docs live in a folder named `build` or `dist` can't be read. Alternatives: honour `.gitignore` instead (less predictable, needs a parser, hidden files still out) or let the owner add exceptions per folder. Recommend **keep the fixed list** for phase 4 and tell the model in the tool descriptions; revisit if it bites.
- **Q3 — When another device opens a file citation, the holding device reads the file silently.** Should the holder show a passing notice ("Read notes/intro.md for your iPhone")? Recommend **no**: they are the owner's own devices, the Folders pane already says folders are read by the agent, and a notice on the Mac nobody is looking at helps no one.

Notes for the owner, not questions: macOS will prompt once for Desktop/Documents/Downloads at attach time (D11); on iOS, files iCloud hasn't downloaded aren't listed until opened once in Files; on Android the storage root, `Download` and `Android/data` can't be attached (system rules); the topic Sources dialog loses "Add folder…" per the earlier decision (files added from folders before stay grouped as they were).
