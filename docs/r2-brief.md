Tests: fakes and recorded fixtures only; never a real model API, never the running service or its data folder.

**Scope.** Three things the RAG doc left for R2, all behind stages that already exist or are added the same way: (1) **reranking** of the fused candidates, listwise on the `Small` route for generation jobs, plus a **local cross-encoder** (ONNX on the CPU) as a registered variant whose promotion to default the eval decides; (2) **query rewriting** as a new stage (`rewriter`), expanding short agent queries and thin lesson plans on the `Small` route; (3) **prompt-version tracking**: every prompt has one versioned, hash-locked constant block, every lesson, proposal and scene records what wrote it, and the eval runner refuses to compare across prompt versions silently. The MCP adapter §4 listed under R2 shipped already as `margin-mcp` (`docs/plan-dogfood.md`) and is out. The service is **Linux-only** now (ONNX on the CPU, `docs/plan-linux-service.md`; the macOS service leftovers are being removed in parallel): nothing here touches Core ML, and the cross-encoder is sized for the 4–8 GB guests of that plan's §3.

**The design in one paragraph.** `retrieve` gains two model-backed stages around what it does today: a `rewriter` before embedding (the plan's strings → more strings, on `Small`, cached, skipped on a retrieval-cache hit) and a `reranker` that can now reach a model (`StageDeps.models`) and knows what it is reranking for (`RerankRequest { purpose, provider, trace_id }`), so `"listwise-small"` grades the 24 fused candidates for lessons and the planner and stays out of the agent tool, while `"onnx-crossencoder"` (a 23–280 MB int8 model on the CPU, loaded on use, unloaded when idle) can serve every purpose if the eval earns it. Every prompt's constant block is versioned and locked in `evals/prompts.lock`; lessons, proposals and scenes record `WrittenWith { prompt_version, pipeline_hash, provider, model, at }`; traces and eval runs carry the versions, and `compare` refuses to mix them silently. Nothing becomes the default by being built: `baseline.toml` keeps `reranker = "none"`, `rewriter = "none"`, and the owner flips Settings after `margin-eval compare`.

### 2. Settled designs

#### D1. The reranker reaches a model and knows its purpose (first commit, `pipeline.rs`, `retrieval.rs`)

R1 froze the stage traits; R2 is the phase the `Reranker` trait was waiting for, so the orchestrator changes it once, in the first commit, and nothing else about the seams:

```rust
/// Why a retrieval runs: stages may behave differently per purpose (a listwise rerank
/// is worth a model call for a lesson, not for every agent search).
#[derive(Debug, Clone, Copy, PartialEq, Eq, Serialize, Deserialize)]
#[serde(rename_all = "snake_case")]
pub enum RetrievalPurpose { Lesson, Plan, Agent, Context }

pub struct RerankRequest<'a> {
    /// The plan's first string, then the others as "Also asked:" lines (`RERANK_QUERY_CHARS` 800).
    pub query: &'a str,
    pub purpose: RetrievalPurpose,
    /// The chat's provider for agent searches; `None` = the default provider (jobs, context API).
    pub provider: Option<Provider>,
    pub trace_id: &'a str,
    /// `job_id` for the model-call trace row (lesson or proposal id), when there is one.
    pub job_id: Option<&'a str>,
}

pub trait Reranker: Send + Sync {
    fn name(&self) -> &'static str;
    fn rerank<'a>(&'a self, req: &'a RerankRequest<'a>, hits: Vec<Hit>) -> BoxFuture<'a, anyhow::Result<Vec<Hit>>>;
}
```

`StageDeps` gains `models: Option<Arc<dyn SmallModels>>` and `tracer: Option<Tracer>`:

```rust
/// What a model-backed stage calls: the small-tasks model of a provider, as a `TextModel`,
/// plus what the trace row needs. The service backs it with `model_for(Route::Small, provider)`
/// + `Generator::text_model`; the eval runner with its own clients (`live.rs`); tests with a fake.
pub trait SmallModels: Send + Sync {
    fn small<'a>(&'a self, provider: Option<Provider>) -> BoxFuture<'a, anyhow::Result<SmallModel>>;
}
pub struct SmallModel { pub model: Arc<dyn TextModel>, pub provider: Provider, pub id: String, pub window: ModelWindow }
```

`Registry::standard(deps)` passes `models: Some(Arc::new(state_models))` from `AppState` (a small `service/src/small.rs`, R2-retrieve); `Registry::new` for tests takes `None`, and a stage that needs a model and has none fails in its constructor with "the reranker \"listwise-small\" needs a small-tasks model; none is configured here" — so `Pipeline::build` (and `parse_variant`'s `unavailable`, `settings.rs:214`) tells Settings which variants this service can't run, as it does for a missing embedder. `retrieval::Request` gains `purpose: RetrievalPurpose` and `provider: Option<Provider>` (the agent tool passes the chat's, `agent_tools.rs:785-800`; `ask.rs` passes `None`; `context_search` passes its `provider` argument). `Hit.rerank` semantics, fixed now: a reranker sets `rerank = Some(grade or score)` on every hit it saw and **rewrites `score`** to `grade + fused_score_normalised` (fused scores min-max scaled into `[0, 1)`), keeping `dense_rank`/`lex_rank`, so the packer's `min_score_pct` threshold and MMR (`mmr-v1`) work unchanged on the reranked order and a rerank never silently unsorts the list. Hits the reranker didn't see (it may cut to `params.max_candidates`) keep their fused score and follow. The eval's `EvalIndex::search` (`index.rs:304`) builds the same `RerankRequest` (`purpose` from the suite: `retrieval` → `Agent` unless the variant's `params.purpose` says otherwise, `courses` → `Lesson`).

#### D2. `"listwise-small"` (R2-retrieve, `service/src/rerank.rs` new)

Registered under `"listwise-small"` with `params { apply_to = ["lesson", "plan"], max_candidates = 24, drop_grade_0 = true, timeout_secs = 20 }`. `rerank`: when `req.purpose` isn't in `apply_to`, return the hits untouched (no call, `rerank_ms` ≈ 0; this is how the agent tool and the context API stay fast by default; a variant can widen `apply_to` for the eval). Otherwise take the first `max_candidates` hits, build the prompt with `pipeline.prompts.rerank(query, hits)` (so `PromptSet` versions it; `LessonV2::rerank` gains the page in the label: "notes/paper.pdf, p. 3, Fourier series > Coefficients"), call `margin_ai::rerank(&*models.small(provider).model, …)` with `CallOptions::new(Route::Small).with_cache_key("rerank:rerank-v1").with_cache_prefix_len(RERANK_CONSTANT.len()).with_prompt_version(RERANK_VERSION).with_max_output_tokens(RERANK_MAX_OUTPUT_TOKENS 400)` under `timeout_secs`; grade 0 hits are dropped when `drop_grade_0` (never below `Budget.passages_min`); then D1's score rewrite. **Every failure (no model, timeout, a refusal, bad JSON) returns the fused order unchanged** and logs a warning: a lesson is never lost to its reranker; the retrieval trace row carries `error_code: "rerank_failed"` and the model-call row (route `Small`, `prompt_version` `rerank-v1`, `job_id`, `parent_id` = the retrieval row's id, `cost_usd`) carries the error as every traced call does. Cost: ≈ 2.5–3k input tokens (the constant block cached from the second call) and ≤ 150 output on `claude-haiku-5-5`/`gpt-6-luna`, under a cent per lesson; latency 1–3 s, hidden inside the lesson job. Because the retrieval cache key includes `pipeline.hash` (which names the reranker and its params) a regenerate or a retried lesson pays nothing. The one generated call goes through `engines::Generator` as a new defaulted method `rerank(&self, m: &ModelChoice, query, candidates, opts)` so `FakeGenerator` scripts it (`rerank_reply: Mutex<Option<Vec<Ranked>>>`, `rerank_requests`), exactly as `plan_course` is scripted today (`tests/common/mod.rs:141-144`); `SmallModels` for the service is a thin adapter over `model_for` + that method.

#### D3. The `rewriter` stage (first commit adds the seam; R2-retrieve fills it)

`PipelineConfig` gains `rewriter: StageCfg` (`#[serde(default = "default_rewriter", skip_serializing_if = "is_default_rewriter")]`, default `"none"`): left out of the JSON while default, exactly as `embedder` is, so every `pipeline_hash` stored before R2 keeps its meaning and the CI baseline doesn't move. `STAGE_KINDS` becomes 8 (`"rewriter"` after `"embedder"`), `stage_name`/`with_stage`/`with_stages_of` learn it, `StageCtor::Rewriter`, `Pipeline.rewriter`, and the registry's trivial `"none"`:

```rust
pub struct RewriteRequest<'a> { pub purpose: RetrievalPurpose, pub provider: Option<Provider>, pub trace_id: &'a str, pub job_id: Option<&'a str>,
    /// What the scope holds, for the prompt: up to 12 document names ("notes/paper.pdf", …).
    pub scope_names: &'a [String] }
pub trait Rewriter: Send + Sync {
    fn name(&self) -> &'static str;
    fn rewrite<'a>(&'a self, req: &'a RewriteRequest<'a>, plan: QueryPlan) -> BoxFuture<'a, anyhow::Result<QueryPlan>>;
}
```

In `retrieve` (`retrieval.rs:1581`): after the cache check (the key stays on the *original* plan; `pipeline.hash` already names the rewriter, so a cache hit skips the model call) and before embedding, `let plan = pipeline.rewriter.rewrite(&rw, req.plan.clone()).await.unwrap_or_else(|e| { warn; req.plan.clone() })`; legs are built from `plan`; the trace row gains `queries: Some(plan.len())` and `legs.rewrite_ms`. `"small-expand-v1"` (`service/src/rewrite.rs` new): `params { min_words = 5, max_added = 2, apply_to = ["agent", "context", "lesson", "plan"], timeout_secs = 10 }`; for `Agent`/`Context` it calls only when the plan's first string has fewer than `min_words` words (§2.3: "when the query is under five words"); for `Lesson`/`Plan` only when the plan has fewer than 3 strings (the planner's questions already make a plan; a lesson from `write_lesson` with no proposal is the case this helps); the call is `margin_ai::rewrite_queries(model, &RewriteInput { query, purpose, scope_names }, opts)` (R2-ai, prompt `rewrite-v1`: "return up to N alternative phrasings or sub-questions a retrieval system should also try; same language; no answers; JSON `{queries: [..]}`", `REWRITE_MAX_OUTPUT_TOKENS` 120, constant-first, cache key `rewrite:rewrite-v1`); the answers go through `QueryPlan::from_strings(original ++ added)` (dedup, trimmed) and an `rewrite_cache` (LRU 1 024 entries keyed by `hash(rewriter cfg, prompt version, purpose, query, scope_names)`) so a repeated agent search pays once. A rewrite that fails or times out leaves the plan as it was. Nothing in the prompt comes from a passage: the input is the query and document *names* only, so a document can't steer its own retrieval.

#### D4. Prompt-version tracking (R2-ai, R2-retrieve, R2-evals, R2-app)

1. **One catalog.** `margin_ai::prompts::catalog() -> Vec<PromptInfo { job: &'static str, version: &'static str, constant_hash: String /* fnv1a-64 hex of the constant block */, constant_chars: usize }>` lists `lesson`, `scene`, `plan`, `rerank`, `rewrite` and the eval prompts (`margin_ai::evals`: `synth`, `grade`, `judge`); the service adds its own (`agent` from `margin_agent::system_prompt()` with `AGENT_PROMPT_VERSION`, `title` and `condense` with their `trace::prompt_version` names) in `service::prompts_catalog()`, served as `GET /api/pipeline/prompts` (first commit: `routes::PIPELINE_PROMPTS`, handler in `settings.rs`, R2-retrieve fills) and printed by `margin-eval prompts`.
2. **A lock in CI.** `evals/prompts.lock` (TOML: `[lesson] version = "lesson-v2" constant_hash = "…"`, one table per job) and a test in `crates/evals/tests/gates.rs` (not ignored; it needs no recording) that fails when a job's `constant_hash` differs from the lock under the same version: "the lesson prompt's constant block changed; bump `LESSON_VERSION` to lesson-v3 and update evals/prompts.lock (`margin-eval prompts --write-lock`)". A bumped version with a new hash passes once the lock is rewritten in the same PR. This is what makes `prompt_version` mean something: the same version is the same bytes.
3. **What wrote it.** `margin_shared::WrittenWith { prompt_version: String, pipeline_hash: String, provider: Provider, model: String, at: DateTime<Utc> }`; `Lesson.written_with: Option<WrittenWith>` and `Proposal.written_with` (`#[serde(default)]`, first commit); `ask::write_lesson` sets it from the writer call's `CallOptions`/`ModelChoice` (and keeps the previous one beside `previous_body` for the restore path), `propose_planned` sets the proposal's from the planner call, `video.rs` records the scene's on the stored video (`StoredVideo.written_with`, service-only). Regenerate overwrites it. The library's public lesson carries it (R2-app shows "Written with lesson-v2 on claude-sonnet-5-5, 14 Oct 09:12" in the lesson's details line, D8).
4. **Traces and runs.** Rerank and rewrite calls carry their versions as every call does; `EvalRun.prompt_versions: Vec<String>` (the versions of every job the run's calls used, sorted; read from the run's own `CallOptions`, and for `courses` from the recorded generations' folder names) and `compare` refuses runs whose `prompt_versions` differ unless `--allow-prompt-change` (warning in the comparison, like providers). `report` prints the versions in its header. `margin-eval prompts [--write-lock]` prints the catalog with each version's hash and whether the lock matches.

#### D5. `"onnx-crossencoder"` (R2-xenc; built as a variant, promoted by the eval)

Behind `margin_embed::Reranker` (`lib.rs:803-809`), a new `crates/embed/src/onnx/rerank.rs` (`cfg(any(target_os = "linux", feature = "onnx"))`): `OnnxReranker::load(files: &RerankerFiles, opts: &OnnxOptions)` opens the model's `tokenizer.json` (`tokenizers` 0.23.2, already a dependency) and `model_quantized.onnx` on the CPU EP with `PreferCPU` and `intra_threads = vCPU − 1` exactly as `session.rs` does; `score(query, passages)` tokenises `[CLS] query [SEP] passage [SEP]` pairs (truncated to `RERANK_PAIR_TOKENS` 512, the query kept whole), runs them in batches of 8 and returns the logit per pair (higher = more relevant; `bge` and `MiniLM` both emit one logit). The session sits in an `IdleSlot` like the vision encoder and is dropped after `ENCODER_IDLE`. Models, selectable by `params.model` and listed in `download.rs` as a second manifest kind (`Manifest::Reranker(RerankerModel)`, next to `Manifest(Backend)`; a `RerankerModel { MsMarcoMiniLmL6, BgeRerankerBase }` enum with `repo()`, `dir()`, `files()`, `version()`):

|---|---|---|---|---|
| `ms-marco-minilm-l6-v2` (default) | `cross-encoder/ms-marco-MiniLM-L6-v2` (ONNX export: `Xenova/ms-marco-MiniLM-L-6-v2`, `onnx/model_quantized.onnx`) | ~23 MB / 90 MB | Apache-2.0 | 22 M params, English, 512 tokens; ~5–10 ms per pair on one CPU core: 24 pairs ≈ 150–250 ms. Fits the agent tool. |

Not candidates on an 8 GB guest beside the 1.6 GB text graph: `BAAI/bge-reranker-v2-m3` (568 M, ~2.2 GB fp32) and `mixedbread-ai/mxbai-rerank-base-v2` (0.5 B), which §2.4 named for the Mac. ### 6. Eval gates and the A/B plan

**Nothing ships as default on being built.** The order, all by hand with `margin-eval` on the dev service (`--service-url https://devmargin.krishnanelloore.com`), after the owner's pending `record-embeddings` + baseline (ROADMAP "Waiting on the owner"):

```sh
margin-eval record-rewrites --variant rewrite-small      # one Small call per golden query/lesson plan, recorded
margin-eval record-reranks  --variant rerank-small       # one Small call per golden query over the baseline's fused 24
margin-eval record-embeddings                            # adds the recorded rewrites' vectors
margin-eval run --suite retrieval --variant baseline
margin-eval run --suite retrieval --variant rerank-small     # purpose = agent unless params.purpose says lesson
margin-eval run --suite retrieval --variant rewrite-small
margin-eval run --suite retrieval --variant rerank-xenc      # on the dev guest (Linux, the real ONNX model)
margin-eval compare <baseline> <rerank-small>
margin-eval compare <baseline> <rewrite-small>
margin-eval compare <rerank-small> <rerank-xenc>
margin-eval run --suite courses --variant rerank-small && margin-eval judge --against evals/recorded/generations/lesson-v2   # faithfulness, both orders
margin-eval run --suite agent --variant rewrite-small                                                                        # the agent suite's one-word questions
margin-eval report <run> --service --service-url …                                                                           # cost of the small route per query/lesson
```

Promotion rules (the owner flips Settings; the integrator commits the matching `baseline.toml` change and the new `baseline.json` in the same PR):

| Variant | Becomes the default when (paired bootstrap 95 % interval, same embedder, same provider, same prompt versions) | Else |
|---|---|---|
| `listwise-small` for `lesson`/`plan` | nDCG@10's interval lower bound > 0 **and** recall@10 not down by more than 1 point **and** the courses judge's faithfulness not down **and** small-route cost ≤ $0.01 per lesson | stays a variant |
| `small-expand-v1` for `agent`/`context` | recall@10 on `lexical` + `semantic` kinds up ≥ 3 points with the interval above 0 **and** negatives' false-positive rate ≤ baseline + 2 **and** p95 `rewrite_ms` ≤ 2 s | stays off for the agent (§2.3 said "off by default for the agent tool and on for generation jobs (eval decides)"); for `lesson`/`plan` the courses suite decides the same way |
| `onnx-crossencoder` for `agent`/`context` | nDCG@10 ≥ `listwise-small`'s − 1.0 point (or ≥ baseline + 3.0 where listwise isn't applied to that purpose) **and** p95 `rerank_ms` ≤ 400 ms for 24 candidates on the dev guest **and** RSS ≤ 400 MB loaded | stays a variant; `bge-reranker-base` is tried only if the corpus isn't English |

CI gates (`cargo test -p margin-evals`, `evals/gates.toml`): the baseline is unchanged by R2 (both stages `"none"`), so the retrieval thresholds hold as they are; new: `[prompts] lock = true` (the lock test, always on); `[rerank] moved_at_10_max = 60` and `fallback_rate_max = 0` on the recorded reranks (a reranker that reorders more than 60 % of the top 10 on the golden set is a bug, not a win); `tool_output_max_bytes` unchanged (a reranked `search` output still ≤ 16 KB). `compare` refuses runs whose `prompt_versions` differ without `--allow-prompt-change`, and a chunker/embedder change still needs `--allow-embedder-change`, so a rerank "win" is never a side effect of fresh vectors or a reworded prompt.

### 7. Review lenses

- **Seams**: the `Reranker` and `Rewriter` traits, `RerankRequest`/`RewriteRequest`, `SmallModels`, `StageDeps` and `PipelineConfig.rewriter` change only in the first commit; every variant is registered by name; `Pipeline::build` fails loudly on a model-backed stage with no model or no download, and Settings shows it as unavailable.
- **Hashes keep meaning**: a config without `rewriter` or with `"none"` hashes as before R2 (the pinned test); the CI baseline doesn't move; `written_with.pipeline_hash` on a lesson equals the trace rows' of its job.
- **Score discipline**: after a rerank the list is sorted by `score` descending, `rerank` is `Some` on exactly the hits the reranker saw, the packer's threshold and MMR run on `score`, grade-0 drops respect `passages_min`; `grep` for a second sort or a bypass of the packer finds nothing.
- **Never a worse lesson**: every rerank/rewrite failure, timeout or refusal returns the input unchanged and is traced with `error_code`; no `?` on a model call inside `retrieve`.
- **Cost and latency are visible**: every small call is a `model_call` row with `parent_id` the retrieval, `route: small`, its version and `cost_usd`; `rerank_ms`/`rewrite_ms` in `legs`; the report's Efficiency section shows the small route; the agent path makes no small call unless a variant says so.
- **Prompt injection**: the rerank prompt tells the model candidates are material (already in `RERANK_CONSTANT`); the rewrite prompt sees the query and document names only, never passage text; both outputs are schema-bound and completed/deduped in Rust.
- **Prompt versions mean bytes**: the lock test runs in CI; a changed constant without a bump fails; `catalog()` covers every prompt the service sends (grep for `Prompt {` and `prompt_version(` literals finds nothing outside the catalog).
- **Memory on the guest**: the cross-encoder loads on use, unloads after `ENCODER_IDLE`, ≤ 400 MB measured; no second ORT environment; `intra_threads` as the text graph.
- **Fakes only**: `FakeGenerator` scripts rerank/rewrite; `FakeReranker` stands in for the ONNX model; the recorded files are the only "real" answers in CI and fail on a miss; nothing reaches Hugging Face or a model API.
- **Every UI element works** (R2-app): the Rewriter row saves through `SettingsPatch.pipeline`, the reranker model row downloads and removes, the lesson details line reads the real `written_with`.

### 8. Risks to settle before branching

- **`Reranker` signature change** touches `NoRerank`, `EvalIndex::search`, `crates/evals/src/{ci,runner,courses}.rs`'s `PromptSet` fakes (they implement `rerank(query, hits) -> Prompt`, unchanged) and nothing else: the first commit does it in one go and `cargo test --workspace` proves it.
- **`StageDeps` is constructed in ~10 places** (`Registry::standard`, `settings.rs` tests, `EvalIndex::build`, `index.rs` tests, `runner.rs`): give it `StageDeps::new(store)` with `models: None, tracer: None` so only the service's call site and the runner change.
- **Score rewriting vs the retrieval cache**: the packed result is cached after reranking, so a reranker change (name or params) must change `pipeline.hash` — it does (`StageCfg.params` are hashed).
- **Recorded reranks go stale** when the baseline's fused candidates change (a chunker or fusion change): the recording is keyed by candidate ids, so a miss fails loudly and the gate says "re-record"; the same rule `RecordedEmbedder` lives by.
- **ONNX export availability** of the two rerankers under the named repos is unverified here (no network in this pass): R2-xenc's first task is to confirm the files (or export with `optimum` once and host them under the owner's Hugging Face account, pinned by revision), as LX did for the embedder.
- **English-only MiniLM**: fine for today's corpus; the eval's `cross-modal` and `negative` kinds will show whether a cross-encoder hurts pictures (it scores OCR text) — `modalities` filtering stays before reranking, and picture hits keep their fused score when `params.pictures = "keep"` (default) so a text-only model can't demote every picture.
