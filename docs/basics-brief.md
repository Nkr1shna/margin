**The design in one paragraph.** ⌘K becomes one `GET /api/search` that answers in two halves from one request: the library half as today, and a *passages* half that is `retrieval::retrieve` with `purpose: Search`, the caller's `Reader`, `Scope::Library`, and no packing, so a person's search is the same hybrid EmbeddingGemma + BM25 pipeline the agent uses (reranker and rewriter per the variant, off for search by default), with the lexical leg's `HIGHLIGHTS` marks and the hit's `Citation` so the app opens the existing viewer at the page, line or second; the eval proves a person and an agent get the same ranked ids. Files, trash, move and offboarding are built on the rows and seams L1/L2 settled (`Owned`, `Ownership::of`, `list_visible`, `set_document_audience`, `audit::record`): a Files screen over `lib.sources`, `PATCH /api/sources/{id}`, a download through each platform's save path; soft delete as `deleted_at` on the six row kinds with passages parked in `passage_trash` (no new predicate inside the KNN scan), an undo toast, a Trash screen and a 30-day purge; `NotePatch.topic_id`/`LessonPatch.topic_id` and a Move dialog plus drag on desktop; a `handover` row whose questions a model writes from the leaver's own documents, answered in text or voice, filed as notes the manager owns with an audience the manager picks, then `POST /api/people/{id}/remove` reassigns what others could read and deletes (after the leaver's own export) what only the leaver could. Office files are read by small pure-Rust readers behind the existing `extract` seam; a URL becomes a source through one fetch route with an SSRF guard; the share sheet is document types on iOS/macOS and a `SEND` intent on Android landing in the upload flow that exists. Usage is one route over `trace` grouped by principal and month; the audit gaps are new `AuditKind`s on L2's table. ### 2. Design decisions

#### D1 settled: search is the retrieval pipeline (B-search; first commit for the types)

`margin_shared`:

```rust
pub enum SearchKind { Topic, Lesson, Note, Passage, Chat }        // + Passage (a file, folder file, transcript or agent document), Chat (a transcript hit)
pub struct SearchHit {
    pub kind: SearchKind, pub id: Id, pub title: String, pub context: String,
    /// Plain text, as today, for Topic/Lesson/Note; for Passage/Chat the matching words are
    /// wrapped in `SEARCH_MARK_OPEN`/`SEARCH_MARK_CLOSE` (`\u{e000}`/`\u{e001}`, never HTML).
    pub snippet: String,
    /// Where to open it (Passage, Chat): the passage's `Citation` as the viewer takes it, the
    /// document id, and for a chat the item id the passage lies in.
    #[serde(default)] pub locator: Option<SearchLocator>,
    #[serde(default)] pub score: f32,
}
pub struct SearchLocator { pub document_id: Id, pub citation: Citation, pub chat_id: Option<Id>, pub item_id: Option<Id> }
pub struct SearchResponse { pub library: Vec<SearchHit>, pub passages: Vec<SearchHit>, pub passages_ms: f64, pub truncated: bool }
```

`GET /api/search?q&k=` (default `SEARCH_K` 20, max 50; `kinds=` optional) returns `SearchResponse`; `library` is `search::run` as today (`list_visible` + the ngram indexes, L2's deny). `passages` is `retrieval::retrieve` with `Request { plan: QueryPlan::single(q), scope: Scope::Library, reader: Reader::of(&p), modalities: [], k, budget: Budget { passages_min: 0, min_score_pct: 0, .. }, purpose: RetrievalPurpose::Search, provider: None, trace_id: new, caller: None }`, **packed by a `"none"` packer**: `PipelineConfig` gains no stage; `retrieve` gets a `pack: bool` on the request (false → every fused hit becomes one `Packed` with its own citation, no merging, no budget; the retrieval cache still applies, keyed as today plus `pack`). `RetrievalPurpose::Search` is the fifth variant; `listwise-small`'s `apply_to` and `small-expand-v1`'s stay as they are (neither names `search`), so a search makes no model call by default and a variant can turn either on for the eval. The snippet: `Hit.highlight` when the lexical leg matched (the service rewrites `HIGHLIGHT_OPEN/CLOSE` to the marks), else the first 160 chars of the passage around the first query word (`search::snippet`), else the passage's start; the app renders marks as `<mark>`. `SearchHit.title` is the document's name (`source.name`, `folder/path`, the lesson/note title, the chat title), `context` the topic breadcrumb / folder / "Chat · 3 Oct". Chat hits: a transcript passage's `Origin::Library { kind: Chat, id }` gives `chat_id`; `item_id` comes from the chat transcript's `section_path`, which `library_text` must name per item (`ingest.rs:521`; today the transcript is one text — B-search makes each item a section `item:<id>` so `document_outline` and search can point into a chat; a re-index of chats follows through the existing generation bump). Lesson and note passages are dropped from `passages` when the same row is already in `library` (one hit per thing). Latency: the dense leg embeds the query on the CPU (~30–60 ms on the dev guest) and the HNSW scan is tens of ms; the palette keeps the 200 ms debounce and shows `library` as soon as it has it (one request, one response: simplicity over a 50 ms gain; owner Q1 for a two-request variant). Every search leaves a `retrieval` trace row with `purpose: search` (D7 adds `purpose` to the row), `principal`, `hit_ids`, never the query text unless `caller` is set (it isn't for people).

**Eval (B-search in `crates/evals`):** suite `search` = the retrieval golden set replayed with `purpose: Search` and `pack: false`; gates `[search] rank_identical = true` (the top `RETRIEVAL_K_FUSED` ids equal the `agent` purpose's with the same variant: a person and an agent see the same order unless a variant says otherwise), `highlight_rate_min = 90` (share of lexical-matched hits with marks), `p95_latency_max_ms = 400` on the recorded vectors; it runs on `FakeEmbedder` in CI like L2's `access_gates` and on the recordings when they exist. `report` gains a "Search" line. A variant `search-rerank.toml` (`apply_to += "search"`) exists for the owner's A/B; nothing turns on by itself.

#### D2 settled: the Files screen (B-app-library; B-library for rename; B-share for download)

`Route::Files {}` (`/files`), a sidebar entry "Files" under Notes, ⌘⇧F (a `Command::Files`). The screen lists every `Source` in `lib.sources` the service gave this reader (L2's `list_visible`, nothing new): columns name (kind icon), where (topic breadcrumb, "Chat · title", or folder), size, status, added; sort by name / added / size / kind (a `sort` in `LocalConfig`, persisted), a filter box like Notes', grouped by folder when sorted by name. A row: **Open** (the row itself) → `CitationViewer` on a synthesised `Citation` (`page: Some(1)` for PDFs, `start_line: Some(1)` for text, `start_ms: Some(0)` for media; `citations::viewer` already renders every kind from a `Citation`); **Rename…** → `PATCH /api/sources/{id}` with `SourcePatch { name: Option<String> }` (owner only, `check_owner`; the service renames `source.name`, the document's `name`, and the on-disk link name through `sources::named_link`; passages and stored citations keep their `source_name`: the viewer reads the source by id, so old lessons still open it; `SourceChanged` + `DocumentChanged`); **Download** (D9); **Delete…** → trash (D3); **Move to topic…** for a topic's file (`SourcePatch.topic_id`, re-stamped by `Ownership::of(topic)` + `set_document_audience`; a folder file can't move: "Files of a folder stay with it"). Phone: rows tap to open, a trailing "…" opens a sheet with the actions. Also reachable: "Show in Files" from the viewer's folder line.

#### D3 settled: trash, undo, restore (B-library; B-app-library)

Soft delete on `topic`, `lesson`, `note`, `chat`, `source`, `workspace`: `deleted_at: Option<DateTime<Utc>>`, `deleted_by: Option<PrincipalId>`, `deleted_with: Option<Id>` (the root of the delete, so restoring a topic restores exactly what went with it and nothing deleted on its own since), all `#[serde(default)]`, indexed (`<table>_deleted ON doc.deleted_at`). Every delete handler keeps its signature and marks instead of deleting: `remove_topic` marks the subtree and everything under it with `deleted_with = topic id`; `delete_lesson_locked`, `remove_note`, `delete_chat` (its items stay; the turn is aborted as today), `sources::delete_locked`, `workspaces::delete_locked` (its files) the same. **What leaves the index at once:** `ingest::trash_document_locked(id)` moves the document's passages into `passage_trash` (`INSERT INTO passage_trash (SELECT * FROM passage WHERE document_id = $d); DELETE passage WHERE document_id = $d`, one indexed statement each, under the write lock), sets `document.status = Trashed`, writes the `document_deleted` tombstone and bumps `generation` (agents and the change feed see it gone, as today), invalidates the retrieval cache. No row with `deleted_at` is ever listed: `state::LIVE_WHERE = "doc.deleted_at = NONE"` is appended by `list_visible`, `get_library`, `search::find`, `chats::list_chats`, `workspaces::list_workspaces`, `folders::files` and every `library::{topic,lesson,note}` by-id read (`readable` → 404 for a trashed row; the grep test §5.10 checks every `SELECT … FROM <library table>` carries it or is in the trash allow-list). Because the passages are *moved*, the KNN and FULLTEXT statements gain no predicate: L2's two conjuncts stay the only ones, and its leakage gate is untouched.

Routes: `GET /api/trash` → `Vec<TrashEntry { kind, id, title, context, deleted_at, deleted_by, deleted_with, bytes }>` for rows the reader may read (`ACCESS_WHERE` + L2 deny, `deleted_at != NONE`), newest first, roots only (a lesson trashed with its topic shows under the topic); `POST /api/trash/{kind}/{id}/restore` (owner, admins not exempt; 409 `parent_gone` when the topic it belongs to is itself in the trash and isn't restored with it — the message names the topic to restore first; a restored topic restores its `deleted_with` set) → clears the three fields, moves the passages back (`INSERT INTO passage (SELECT * FROM passage_trash WHERE document_id = $d); DELETE passage_trash …`), `document.status` back to `Ready`, bumps `generation`, emits the row's `*Changed` to its audience (the app re-adds it; sockets of readers who lost access since are not told, L2's rule); `DELETE /api/trash/{kind}/{id}` purges now (the old hard delete, `delete_locked` renamed `purge_locked`), `DELETE /api/trash` empties the reader's trash. A daily job (`trash::purge_expired`, beside `trace::apply_retention`) purges rows with `deleted_at < now − TRASH_KEEP_DAYS` (30; `Settings.trash_keep_days`, admin). Audit: `AuditKind::Trash { Delete | Restore | Purge }` rows with the subject id and kind only (D7). Events: `Event::Trashed { entry }` and `Event::Restored { kind, id }` to the row's audience so Trash screens update live; the `*Deleted` events keep going out at trash time (every store already drops the row on them).

App: after every delete the `ConfirmDialog` stays (one tap on phones is too easy to hit; owner Q3), its text changes to "Moves … to the Trash. You can restore it for 30 days.", and on success a toast "Deleted ‘Fourier series’. **Undo**" (8 s) calls restore and re-navigates when the deleted screen was open. `Route::Trash {}` (`/trash`), a sidebar entry under Files with a count: a list with kind icon, title, where, when, Restore and Delete now; Empty trash… with a confirm. `ConfirmDialog` loses "This can't be undone." everywhere except purge.

#### D4 settled: move and reorder (B-library; B-app-library)

#### D8 settled: offboarding, removal, export (B-people; B-app-org)

**The handover session** (owner's design, made concrete):

```rust
// margin_shared
pub struct Handover { pub id: Id, pub person_id: Id, pub started_by: Id, pub manager_id: Id,
    pub status: HandoverStatus /* Questions | Answering | Done | Cancelled */,
    pub questions: Vec<HandoverQuestion>, pub topic_id: Option<Id> /* where the answers were filed */,
    pub audience: Audience /* L2's; what the filed notes get */, pub created_at, pub updated_at }
pub struct HandoverQuestion { pub id: Id, pub text: String, pub why: String /* one line: what it draws on */,
    pub from: Vec<Id> /* document ids it was written from */, pub answer: Option<HandoverAnswer>, pub skipped: bool }
pub struct HandoverAnswer { pub text: String, pub source_id: Option<Id> /* the voice recording, when spoken */, pub at: DateTime<Utc> }
```

Routes (`/api/people/{id}/handover`): `POST` (an admin for anyone; a person for themself) with `{ manager_id, audience }` creates the row and starts the question job; `GET` (the person, the manager, admins); `PUT …/answers/{qid}` `{ text }` or `{ source_id }` (the person only; a voice answer is an audio source uploaded to the handover's private topic through the ordinary upload path, transcribed by Parakeet as every audio source is, and its transcript becomes `answer.text` when the source is `Ready`, so no new recorder on the service: the app records with the platform's microphone and uploads a `.m4a`/`.webm`, owner Q6 on the recorder); `POST …/finish` (the person or the manager) files the answers; `DELETE` cancels. **Questions:** `handover::write_questions(state, &handover)` on the writing route (`Route::Writer`? the lesson writer's slot, provider default) with prompt `handover-v1` (`margin_ai::prompts`, versioned, locked, `catalog()`): constant block (role, "write 10–20 questions only this person can answer; each names what it draws on; no answers; JSON"), variable block = a `retrieve` over the leaver's **own** documents (`Request { scope: Scope::Library, reader: Reader::of(&leaver principal), purpose: Handover, k: 40, pack: true }` filtered to `document.owner == leaver`, plus the titles of their topics, chats and notes, plus the decisions they wrote (`ingest_document kind: decision` rows are notes), plus references to them in others' documents the leaver can read: the "gaps" are things named but not documented — `Small` route `handover-gaps-v1` lists terms that appear in the leaver's chats but in no document); output completed in Rust (dedup, cap `HANDOVER_QUESTIONS_MAX` 20, drop empty). Through `Generator::handover_questions` so `FakeGenerator` scripts it. **Filing:** `finish` creates topic "Handover: @alice" owned by `manager_id` with `audience` (L2's `audience::set` rule: the manager is always in `access`; the leaver's `person/<id>` is added so they can read what they wrote until removal), one note per answered question (title = the question, body = the answer with "Asked because: …" and the source documents cited by name), indexed like every note; the voice recordings move to that topic (`SourcePatch.topic_id`, D2). `AuditKind::Handover`. **App:** Organisation → a person's row → "Start offboarding…" (admin) / Settings → Account → "I'm leaving: start my handover" (self); a `HandoverScreen` (`/handover/:id`): the questions one by one, a text field and a Record button (desktop and phones; the recording shows as a source line with its transcript when ready), Skip, "Finish and file"; the manager sees progress ("7 of 14 answered"). Phone-first: one question per screen.

**Removal.** `POST /api/people/{id}/remove { reassign_to: Id, private: "delete" | "transfer" }` (admin, not self, not the owner; the person need not be disabled first): under the write lock, for every row kind with `owner == id` (topics, lessons, notes, chats, sources, workspaces, agents, handovers): rows whose audience reaches anyone but the leaver (`access − {person/<id>}` non-empty) → `owner = reassign_to`, `access` keeps the audience with `person/<id>` swapped for `person/<reassign_to>`, documents and passages re-stamped (`set_document_audience`); rows private to the leaver → `private: transfer` makes them the new owner's private rows (an explicit, audited choice: L2 Q3 says admins read no private KB, so the default is `delete`), `private: delete` purges them through D3's purge (no trash; it's gone with the person); chats are always deleted (their transcripts are the leaver's words to Margin; owner Q7); agents are deleted with their tokens revoked (an agent's ceiling was the leaver's); devices revoked; group memberships removed; invitations by them kept; `person.state = Removed` (a new `PersonState`, row kept for audit and attribution, handle kept unique, GitHub login released); `AuditKind::PersonRemoved { reassigned_to, counts }`; events: `PersonChanged`, `*Changed` for every re-owned row to its audience, `AccessChanged`. The app: "Remove @alice…" → a dialog: pick who receives their shared work (a person picker), what happens to private notes and chats (delete / transfer), a count of each ("12 topics shared with @engineering move to @bob; 3 private topics and 8 chats are deleted"), the sentence "Start a handover first?" with a link when none exists. **Export my data:** `GET /api/me/export` (any person, themselves only; 1/min) streams a zip: `{topics,lessons,notes,chats,sources,workspaces}.jsonl`, `notes/*.md`, `lessons/*.md`, `chats/*.md` (transcripts), and the original files of their sources (`sources/<id>/<name>`), everything by the reader rule (what they can read, owner or not? owner Q8: recommend **what they own** plus what's private to them); Settings → Account → "Export my data" saves it through D9's save path. L2's host-side `margin-service export --person` stays the admin/owner path and is unchanged. Removal refuses (409 `export_pending`) when the person is active and never exported, unless `force: true` with the audit row saying so; owner Q7.

### 7. Review lenses

- **One retrieval.** `search.rs` calls `retrieval::retrieve` and nothing else for passages: no `SELECT … FROM passage` in `search.rs`, no second scoring, no substring scan over passage text; the marks come from the lexical leg's `HIGHLIGHTS` or `search::snippet` on the hit's text; `Reader::of(&p)` is the reader, never `access: None`.
- **Trash is invisible everywhere.** The grep test (§5.10) is the mechanical lens; by hand: no `deleted_at` check done client-side as the only filter; `passage` holds no row of a trashed document (count test); restore re-embeds nothing (the fake embedder's counter); purge is the only hard delete and only `trash.rs` and `remove_person` call it.
- **L2's rules hold.** Re-homing and reassignment go through `Ownership::of` + `set_document_audience` + L2's event rule; no new predicate inside the KNN/FULLTEXT statements (`grep CONTAINS` in `retrieval.rs` unchanged after B-library); the handover's question job retrieves as the *leaver's* reader and filters to their own documents; filed notes get the audience the manager chose, never wider than the manager can read (`audience::validate`); admins read no private content anywhere (the Remove dialog shows counts, not titles, of private rows).
- **Nothing leaves the service.** The web page fetcher refuses private addresses after resolution and re-checks each redirect; feedback goes only to the owner's service and its configured webhook; the export is the person's own rows; no telemetry.
- **Audit has ids only.** Every new `AuditKind`'s `before`/`after` serialises to ids, kinds, counts, prefixes (a test per kind).
- **Toasts, one host.** `grep "crash-notice\|announce("` finds only the host and the live region's sink; every completion string goes through `app.toast`; no second floating card component.
- **Every UI element works** on macOS, iOS and Android widths: Files/Trash/Handover/Help as full screens on phones, dialogs as sheets, drag has a keyboard and menu equivalent, copy buttons are visible without hover, downloads land in the platform's save UI, the share path is exercised on each platform in the manual list.
- **Strings.** Every refusal says what to do; dialog texts say "Trash" not "delete forever" except purge; "Only you" / "@engineering" summaries from L2 are reused in the handover audience picker.
- **Fakes only.** `FakeGenerator.handover_reply`, `FakeSourceTools` for Office in service tests (the real readers are tested in `crates/embed`), a local axum site for web pages, an injectable resolver for the SSRF guard; no network, no model API, no running service.
- **Builds.** `deploy/local/linux-check.sh` before each PR; `cargo test --workspace`, clippy, fmt, the iOS check and the Android build after integration (the manifest patch is part of that build).

### 8. Risks to settle before branching

1. **`INSERT INTO passage_trash (SELECT … FROM passage WHERE document_id = $d)` on SurrealDB 3.3.4**: verify on kv-mem and on a SurrealKv copy that it copies `vector` (F32 arrays) intact and runs in ≤ 2 s for 5 000 rows; if the copy is slow or lossy, the fallback is B-library's alone: delete the passages at trash time and **re-queue ingest at restore** (the file stays), accepting a re-embed on restore. Settled in B-library's first day, reported in its PR.
2. **`DEFINE FIELD deleted_at` on populated tables** rewrites nothing (an `option<datetime>` with no default); the indexes build once at the next start (phase 5's schema guard backs up first).
3. **dx 0.7.9's Android manifest** is generated into the Gradle project; the `build.rs` patch relies on the file's location relative to `WRY_ANDROID_KOTLIN_FILES_OUT_DIR` and on `</activity>` being there once. If dx grows a manifest-override setting, use it; if the location differs, the patcher reads `WRY_ANDROID_KOTLIN_FILES_OUT_DIR`'s ancestors for `AndroidManifest.xml` and fails the build loudly when it finds none. B-share's first task.
4. **iOS `openURLContexts` under Margin's own scene delegate** (`scene.rs`): the delegate is Margin's, so the callback is ours to implement, but the cold-start case (`willConnectToSession:options:` with `urlContexts`) arrives before Dioxus has a window; `shared_in` is a signal read by the root component once it mounts, so nothing is lost. Verify on the simulator with `xcrun simctl openurl` and a file from Files.
5. **A true iOS share extension** (Margin in the share sheet from Safari) is not buildable with dx: owner Q10; nothing here depends on it.
6. **Search latency on the dev guest** (2–4 vCPU): the dense leg embeds the query on the CPU (~60 ms) on top of the library lookup; the palette debounces 200 ms and the `[search]` gate's 400 ms p95 is measured on the recordings, the service-side p95 by `perf`; if typing feels slow, owner Q1's two-request variant (library first, passages after) is one flag in the palette.
7. **Chat transcripts as per-item sections** change `library_text` for chats: every chat re-indexes once (the diff keeps unchanged passages; `section_path` changes make them "moved", not re-embedded: `ingest::moved` handles locator-only changes). Checked by a test on the fake embedder's call count.
8. **Voice answers depend on the speech model** being downloaded on the service (Parakeet, LX): without it the recording is `Ready` with no transcript, and the handover shows "Transcription needs the speech model; type the answer or ask an admin to download it in Settings → Sources" (the existing `no_transcriber` sentence). Not a new path.
9. **Removal and L2's export**: `margin-service export --person` runs on a stopped copy; `GET /api/me/export` runs live for the person themself. They are different things for different people; the brief keeps both and the Remove flow points admins at the host command for a leaver who is already gone. Owner Q7/Q8.
10. **`zip`/`quick-xml`/`calamine` compile on macOS** for `cargo check` and tests (pure Rust, no system library); the Office readers run in `spawn_blocking` like pdfium; a 50 MB pptx with a thousand slides is read in seconds; memory is the unzipped XML (bounded by `WEBPAGE_MAX_BYTES`-style caps: `OFFICE_PART_MAX_BYTES` 64 MB per part, else `Extract` error).
