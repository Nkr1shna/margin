**Scope.** The plan's L2: every read of indexed content carries the reader's access *inside* the SurrealDB statement (both legs of the hybrid query, by-id reads, the change feed, ⌘K), with hierarchical groups, grants and denials, agents limited by their owner's ceiling, private knowledge by default and publishing; derived content carries the audience of what it drew on; an audit trail says who changed what; the app gets the Audience control and the admins' Audit view; the eval suite gets a leakage gate and proves the owner's retrieval numbers don't move. Shape as `docs/l1-brief.md`: one first commit by the orchestrator, areas in worktrees with exclusive files, integration + e2e, two reviewers, a fixer; the Fable architect reviews this brief first. Tests on fakes and in-memory SurrealDB only; never a real model API, never the running service or its data. The service is Linux-only; every UI element works on desktop, iOS and Android.

### Decided by the owner (binding here; plan §9, every recommendation accepted 2026-10-14)

- **Q3** Admins cannot read private knowledge bases; the only path is a logged, owner-only export on the service host (built here, D7).
- **Q4** Derived content whose sources have different audiences falls back to **private to its creator** with "Publish…" one click away; never the widest common ancestor.
- **Q5** An agent's ceiling is a subset of its owner's access; Margin's own agent (a chat turn) runs with the owner's full access; external and voice agents exclude the private KB by default (L1 built the defaults; L2 makes them mean something).
- From L1 (`docs/l1-brief.md` §8): admins are not exempt from `not_owner`; a second *untrusted* person waits for L2 — this phase is what makes one safe.

**The design in one paragraph.** A `Reader { paths, deny_ids }` built only from a `Principal` becomes a required part of every retrieval query, and every statement over `passage` and `document` carries two conjuncts inside the scan: `access CONTAINSANY $paths AND deny CONTAINSNONE $deny`. The prefix expansion (`visible_paths`, `may_see`) goes; hierarchy stays where L1 put it, in the caller's expansion. `passage` and `document` gain `deny`; a one-pass migration `passages-access-v1` re-stamps every document and its passages from the row that owns it (so the owner's library, private since `people-v1`, becomes private in the index too, and agent documents become private to their owner). Publishing is one route over the units of audience (topic, folder, standalone source, agent document; lessons and notes follow their topic, chats stay private in L2), journaled to a new `audit` time series and cascaded down to passages in one indexed `UPDATE`. A lesson or proposal written from passages gets the audience those passages allow (`margin_shared::audience::derive`: the widest audience whose every reader can read every source; else private to the creator with a notice). Agents read within `owner ∩ ceiling` as before and can now be named in `deny` (and in `access`). Every by-id read, the change feed, ⌘K and the rewriter's names carry the same conjuncts; the retrieval cache keys on them. The eval suite gains principals and audiences over the fixture corpus: a leak is a failed build, and the owner's ranked results are identical to the baseline's.

### 2. Design decisions

#### D1 settled: the reader, the two conjuncts, no prefix expansion (first commit `pipeline.rs`/`retrieval.rs`/`db.rs`; L2-retrieve builds)

```rust
// crates/service/src/pipeline.rs (the stage seam; frozen after the first commit)
/// Who is reading: bound as `$paths` and `$deny` inside every index statement. Built
/// from a `Principal` in the service (`Reader::of`), from the golden principals in the
/// eval runner. There is no "everything" reader.
#[derive(Debug, Clone, PartialEq, Eq, Hash)]
pub struct Reader {
    /// The expanded read set: `person/<id>`, `company`, every group and ancestor; for an
    /// agent, `owner ∩ ceiling ∪ { agent/<id> }`.
    pub paths: Vec<String>,
    /// What a `deny` entry can name for this reader: the person's paths; for an agent,
    /// the owner's `deny_ids ∪ { agent/<id> }` (a deny on the owner denies the agent).
    pub deny_ids: Vec<String>,
}
impl Reader {
    pub fn of(p: &Principal) -> Self;       // service: the only constructor outside tests
    pub fn sql() -> &'static str { " AND access CONTAINSANY $paths AND deny CONTAINSNONE $deny" }
    pub fn binds(&self) -> Vec<(&'static str, Value)>;   // ("paths", ..), ("deny", ..)
}
pub struct Query { …, pub reader: Reader, … }           // was `access: Option<Vec<String>>`
```

`retrieval::Request.access: Option<Vec<String>>` becomes `reader: Reader` (required). `Filter` loses `access`/`visible_paths`; `Filter::sql()` appends `Reader::sql()` always, `binds()` the reader's; `may_see` and `visible_paths` are deleted (nothing else may re-implement a prefix rule: a reader in `company` does **not** see `company/sales`). `scope_names` filters with `reader.allows(&doc)` (exact: `doc.access ∩ paths ≠ ∅ ∧ doc.deny ∩ deny_ids = ∅`), `legacy_hits` with the source owner's `person/<id>` ∈ `paths` (legacy rows exist only before `passages-v1` finishes). The retrieval cache key replaces `"access": req.access` with `"reader": reader` (both arrays, sorted). `ContextQuery.access` stays on the wire (`Option<Vec<String>>`, the subset a caller may narrow to); the handler builds `Reader { paths: query_access(&p, asked)?, deny_ids: p.deny_ids }` so a narrowed `access` never loosens a deny. `ask.rs` builds the lesson's and planner's `Reader` from the job's principal (`person_principal(topic.owner)` — the topic owner's access at the time the job runs; the lesson is theirs).

**Schema (first commit, `db.rs`):** `DEFINE FIELD IF NOT EXISTS deny ON passage TYPE array<string> DEFAULT []`, `DEFINE INDEX IF NOT EXISTS passage_deny ON passage FIELDS deny.*`, `DEFINE INDEX IF NOT EXISTS document_deny ON document FIELDS doc.deny.*`; `passage.access`'s default becomes `[]` through the fingerprinted `OVERWRITE` block (`DEFINE FIELD OVERWRITE access ON passage TYPE array<string> DEFAULT []`) so a row written without an audience is visible to nobody rather than to everyone; `PassageRow.deny: Vec<String>` (`#[serde(default)]`), `Document.deny` (`#[serde(default)]`), `Document.access` default `[]` (read empty = `[person/<owner>]`, `Owned::audience`, as the library rows already do). `Store::set_document_audience(document_id, access, deny)`: `UPDATE passage SET access = $a, deny = $d WHERE document_id = $id RETURN NONE` (the `passage_document` index) plus the `document` row, under the write lock, bumping `generation` so caches and the change feed move. `Store::insert_many`/`update_passages`/`rewrite_vectors` carry `deny`. `SCHEMA_VERSION` → 2 (phase 5's guard backs up before migrating).

**EXPLAIN tests (first commit, `db.rs`, on kv-mem):** the dense statement with both conjuncts plans as `KnnScan` with the predicate holding both `CONTAINSANY` and `CONTAINSNONE`; the FULLTEXT statement (`text @0@ $q … AND access CONTAINSANY $paths AND deny CONTAINSNONE $deny`) plans on `passage_text` with the predicate; a reader with an empty `deny_ids` and a passage with an empty `deny` match (`[] CONTAINSNONE []` is true). **If `CONTAINSNONE` is not accepted inside the KNN predicate on SurrealDB 3.3.4**, the first commit tries `array::intersect(deny, $deny) = []` and `NOT (deny CONTAINSANY $deny)` in that order; if none plans inside the scan, the orchestrator reports it before branching (risk §8.1): the dense leg would need an over-fetch and an in-Rust drop, which breaks the plan's "no post-filter" rule and is a decision for the owner, not an area.

**What never changes:** the rule is two conjuncts, bound from a `Reader`, inside the scan, in every statement that reads `passage` or `document` content — the retrievers' legs, `read_passages`, `passages_on_page`/`passages_by_ord`, `document_outline`, `doc_info`/`doc_state`, `changes_page`, `scope_names`, the picture lookups behind `view_picture`, and the "find the page's twin" `unit_id` lookup. Writers by `document_id` under the write lock (ingest's diff, `update_passages`, `rewrite_vectors`, delete) read without a reader: they act for a document the caller already passed the check for, and the review lens lists them by name.

#### D2 settled: the migration `passages-access-v1` and what stamps a document (first commit stub; L2-write builds, `ingest.rs`, `audience.rs`)

`audience::of_document(state, &doc) -> Ownership` resolves the owning row: `Origin::Library { kind, id }` → the lesson/note/chat row's `owner`, `audience()`, `deny()`; `Origin::Source { source_id }` → the source's; `Origin::FolderFile { workspace_id, .. }` → the folder file's source row (which copies the folder's); `Origin::Agent { .. }` → the document's own `owner`/`access`/`deny` (an agent document is its own unit: `[person/<owner>]` unless it was ingested or published with an audience). A document whose owning row is gone keeps what it has. `upsert_document` and every re-index (`ingest.rs:1641`) stamp `doc.access`/`doc.deny` from it, so the passages written by the diff carry the audience in the same write (today they copy `doc.access`; L2 copies both).

`passages-access-v1` (`audience::migrate`, after `people-v1` in `Service::start`, recorded in `SettingsRow.migrations`, under `write_lock`, idempotent): for every `document`, `set_document_audience(id, of_document(doc))`; agent documents from before L2 become `[person/<owner>]` (the owner `people-v1` gave them); log counts. Nothing is deleted. After it, **nothing in the index says `company` unless a row was published to `company`**: the migrated owner's library (private since `people-v1`) is private in the index too. Consequence for the dogfood agent `claude-code` (an `External` agent with the default ceiling, no private KB): it sees **nothing** until the owner widens its ceiling to include "My private notes and chats" (one click in Organisation → Agents, L1 D10) or publishes the Margin topic to `company` (D3). The migration logs that sentence when the org has one person and at least one agent without `person/<owner>` in its ceiling. Owner Q4.

#### D3 settled: audiences, publishing, cascade, events (first commit routes/types; L2-write builds `audience.rs`)

The alphabet of an audience entry is L1's `PrincipalId`: a group path, `person/<id>`, `agent/<id>`. `margin_shared::audience`:

```rust
pub struct Audience { pub access: Vec<PrincipalId>, pub deny: Vec<PrincipalId> }   // the wire body
pub enum AudienceUnit { Topic, Workspace, Source, Document }                        // what can be set by hand (L2)
pub fn validate(a: &Audience) -> Result<(), String>;   // alphabet, no duplicates, ≤ AUDIENCE_MAX (64) entries each
```

| Route | Who | Does |
|---|---|---|
| `PUT /api/audience/{unit}/{id}` body `Audience` | the row's owner (admins are not exempt, Q3) | validates (every group path exists: 400 `unknown_group`; every `person/<id>` is an active person: 400 `unknown_person`; every `agent/<id>` is one of the caller's agents: 400 `unknown_agent`); stores `access = [person/<owner>] ∪ a.access` (the owner is never locked out) and `deny = a.deny − {person/<owner>}`; **cascades** (below); journals an `audit` row `audience_change` with `before`/`after` (ids and paths); emits events (below); 404 outside the caller's access, 403 `not_owner` for someone else's row |
| `GET /api/audience/{unit}/{id}` | anyone who can read the row | the stored `Audience` plus `inherited_from: Option<(AudienceUnit, Id)>` (a lesson's topic) — the app reads rows' `access`/`deny` already; this exists for documents, which the app doesn't list |

Units and the cascade: **topic** → every topic in its subtree, their lessons, notes, videos, sources, and the documents and passages of all of them; **workspace** (folder) → its sources (the folder files) and their documents; **source** without a topic → itself and its document; **document** of `Origin::Agent` → itself. Lessons and notes **follow their topic** (no per-lesson audience in L2; the UI says so; a lesson's audience may be *narrower* than its topic's by derivation, D4, never wider). **Chats stay private to their owner in L2** (no unit; owner Q3): a chat's transcript holds Passages cards with text from documents its owner could read, and sharing it needs the derivation of D4 over every card or L3's comments; the rows keep `access`/`deny` for L3. `ContextIngest` gains `#[serde(default)] audience: Option<Audience>` (an agent may name only paths within its own `paths`, else 400 `bad_access`; a person any existing group/person; default private), and `margin-mcp ingest --access company/engineering,person/<id>`.

Cascade rule for the subtree: a row under a topic takes the topic's `access`/`deny` exactly (L1's "the topic is the unit"), **except** derived rows (D4) whose stored `audience_narrowed` is set: they take `derive([topic's new audience] ++ their sources' audiences)` again, so publishing a topic can un-narrow a lesson whose sources were the topic's own. Sources that are a folder's files aren't reachable from a topic (they belong to the workspace) and vice versa; `sources::adopt_into_topic`'s existing union-of-audiences for the events stays.

Events: after the write lock, the row's `*Changed` event through `emit_row(&new.access, ..)` (so new readers get the row), `DocumentChanged` for each re-stamped document to its **new** audience (`ingest::document_audience` becomes `Paths(doc.access)`; it widens from `Person(owner)`), and one `Event::AudienceRevoked { unit, ids: Vec<Id> }` to `Paths(old − new)` and `Paths(deny added)` so readers who lost access drop the rows from their store without a reload (the app applies it per kind: topics' subtrees, sources, workspaces). `AccessChanged` is not emitted (expansions don't change).

Defaults, restated: a new topic/chat/folder/source/agent document is `[person/<creator>]`; a lesson/note under a topic copies the topic's; a sub-topic copies its parent's; nothing is `company` unless published.

#### D4 settled: derived audiences (first commit `margin_shared::audience::derive`; L2-write applies it)

A reader `R` with expanded paths `P` reads audience `A` iff `P ∩ A.access ≠ ∅ ∧ P ∩ A.deny = ∅`. The derived audience of sources `A₁…Aₙ` must satisfy: every reader of the result reads every source. `derive(creator: &PrincipalId, sources: &[Audience]) -> Derived { audience: Audience, narrowed: bool }`:

- `access` = the minimal elements (by the ancestor order on group paths; `person/*` and `agent/*` are only equal to themselves) of `{ p ∈ ⋃ Aᵢ.access : ∀ i, ∃ a ∈ Aᵢ.access with a ⊑ p }`, where `a ⊑ p` means `a == p` or `a` is an ancestor of the group path `p`. Expansions are ancestor-closed, so a reader of `p` holds every ancestor of `p`, hence reads every source. Then `∪ {creator}`.
- `deny` = `⋃ Aᵢ.deny` (a deny on any source denies the result) `− {creator}`.
- `narrowed` = the set above (without the creator) is empty: the result is private to the creator, and the UI shows the notice.

Worked: `[company/engineering]` with `[company/engineering/platform]` → `[company/engineering/platform]`; `[company]` with `[company/engineering]` → `[company/engineering]`; `[company/sales]` with `[company/engineering]` → private, `narrowed`; `[person/bob, company/eng]` with `[person/bob, company/hr]` → `[person/bob]`; identical arrays → that array. Property test (shared): over random trees, audiences and readers, every reader of `derive(..)` reads every source, and no wider audience of the same alphabet does (maximality on the tested samples). Where it applies in L2:

1. **Lessons** (`ask::write_lesson`, the `write_lesson` tool, regenerate): `derive(person/<topic owner>, [topic.audience] ++ packed passages' documents' audiences)` — the lesson is never wider than its topic; `Lesson.audience_narrowed: bool` (`#[serde(default)]`) is stored when it fell to private; the lesson's document and passages follow (D2).
2. **Proposals** (`propose_planned`): the same from the planner's retrieval; a course accepted from a narrowed proposal makes lessons that derive again from their own passages.
3. **Notes written by the agent** (`create_note`, `append_to_note` with passages in the turn): a note under a topic follows the topic (L1); the agent's text may quote a passage — the turn ran as the chat owner, and the note is the owner's (private) or the topic's; a note under a topic whose audience is wider than a quoted passage's is the one leak derivation can't see without parsing the note. Rule: `create_note` from a turn whose packed passages (this turn's Passages cards) are narrower than the target topic's audience is refused with "The note would quote documents the topic's readers can't see; file it in a private topic." (the tool output; the agent picks another topic). Pinned by a test.
4. **Retrieval cache**: keyed by the reader (D1), so a packed result never crosses principals.
5. **Traces** keep ids only (built).

Publishing a source later does not re-derive lessons by itself; the topic cascade (D3) does when the topic is published.

#### D5 settled: by-id reads, the change feed, ⌘K, pictures (L2-retrieve)

- `retrieval::{read_passages, passages_on_page, passages_by_ord, document_outline, doc_info, doc_state, frame_lookup}` take `&Reader`; `doc_state` answers `Unknown` for a document the reader can't read (so `readable` is 404, never 403). `context_api::{outline, passages}` and `agent_tools::{read_passage, document_outline, view_picture}` pass `Reader::of(&p)`. `view_picture`'s signed media URL is minted after the check (the URL itself stays unprincipaled and short-lived, phase 5).
- `GET /api/context/changes`: `changes_page(state, &reader, since, limit)` adds the two conjuncts on `document` (`doc.access.*`/`doc.deny.*`); `Tombstone` gains `access`/`deny` (copied from the document at deletion) and the deleted list is filtered the same. A publish bumps `generation`, so a reader who gained access sees the document appear in their feed; one who lost it sees nothing further (no tombstone: the document exists, for others).
- ⌘K: `ACCESS_WHERE` gains `AND doc.deny CONTAINSNONE $deny` (`<table>_deny` indexes on the seven library tables), `access_binds` binds `deny`; `can_read` evaluates `deny` (`row.deny() ∩ p.deny_ids = ∅`). `list_visible` and every `library::*` helper inherit it.
- `trace.hit_ids`: unchanged (ids). `GET /api/traces` stays admin-only.

#### D6 settled: agents (L2-retrieve for the principal; L1's files untouched but `agents.rs` one function)

`agents::agent_principal` sets `paths = (owner.paths ∩ ceiling) ∪ { agent/<id> }` and `deny_ids = owner.deny_ids ∪ { agent/<id> }`; `Reader::of` copies them. So: an agent reads only what its owner reads (access intersected, deny inherited), a row may deny one agent by name (`deny: ["agent/<id>"]`: "not my coding agent"), and a row may be shared with one agent only (`access: ["agent/<id>"]`, readable by that agent and the owner). Margin's own chat turns keep running as the chat owner's person principal (full access, Q5); binding a chat to an agent's ceiling is L3's (mentions) and is not built here. `ceiling_rows` in the app already lists the private KB as its own row. Agent tokens' rate limits are phase 5's.

#### D7 settled: the audit trail and the owner-only export (L2-audit, `audit.rs` new, `export.rs` new)

### 7. Review lenses

- **Two conjuncts, inside the scan, everywhere.** The grep test (§5.10) is the mechanical lens; by hand: no `may_see`, no `visible_paths`, no prefix comparison on access paths anywhere in `crates/service` or `crates/evals` (the hierarchy is only in `groups::expand`/`ancestors`); `Reader` is constructed only by `Reader::of(&Principal)` outside tests and the eval fixture; no `.retain`/`.filter` on hits by access after a query (a post-filter is a review failure even when it is "also" done in SQL).
- **Private by default.** `grep "ACCESS_COMPANY"` in `crates/service/src` finds only the constant's definition, `ROOT_GROUP`, `expand`, and the migration's reading of old rows; no literal `["company"]` audience in a non-test file; `passage.access`'s default is `[]`.
- **Derivation is conservative.** `derive` is the only function that computes an audience from others; it is never given the *reader's* paths (that would widen to the reader); `audience_narrowed` is set exactly when the result is the creator alone.
- **Cascade is complete.** Publishing a topic re-stamps every row under it and every document and passage of those rows in one write-lock section, then emits; a test counts passages by `document_id` with the new audience; nothing stays at the old audience.
- **Agents never exceed owners.** `agent_principal`: `paths ⊆ owner.paths ∪ {agent/<id>}`, `deny_ids ⊇ owner.deny_ids`; the context API's `bad_access` holds for the agent's own paths; ingest audiences within paths.
- **Admins read no content.** No admin bypass in any `can_read`, `readable`, `Reader` or route; `GET /api/audit` joins names only through `can_read`; `export` is a host command on a copy, logged.
- **Events follow the audience.** `DocumentChanged` is `Paths(doc.access)`; `AudienceRevoked` goes to `old − new` and the added denies; `AuditAppended` to `Admins` only; `emit_row` never gets an empty slice.
- **Cache and feed can't cross readers.** The cache key holds `reader`; a publish bumps `generation`; `changes_page` and tombstones carry the conjuncts.
- **No content in audit.** `before`/`after` hold ids, paths, roles, ceilings, token prefixes; a test serialises every instrumented change and asserts no title, name or text.
- **Strings.** Every refusal says what to do; the app shows the service's sentence; "Only you" / "Everyone at the company" / "@group and n people" are the summaries, never paths.
- **Fakes only.** No test reaches a model API, the running service or its data; the eval gate runs on `FakeEmbedder` when the recordings are absent and is never skipped.
- **Every UI element works** on macOS, iOS and Android widths: the control is a sheet on phones, pickers scroll, Save/Cancel reachable, the Audit table pages.
- **Builds.** `deploy/local/linux-check.sh` before the PR; `cargo test --workspace`, clippy, fmt, the iOS check and the Android build after integration.

### 8. Risks to settle before branching

1. **`CONTAINSNONE` inside the KNN predicate is unverified** on SurrealDB 3.3.4 (`CONTAINSANY` is proven, `db.rs:1385`). The first commit's EXPLAIN tests settle it; the fallbacks are named in D1; if none plans inside `KnnScan`, the orchestrator stops and asks (owner Q6) rather than shipping a Rust post-filter quietly.
2. **`DEFINE FIELD OVERWRITE … DEFAULT []`** on a populated `passage` table: verify on kv-mem and on a SurrealKv copy that it changes the default only (no rewrite of rows, no index rebuild); if it rebuilds, the default stays `['company']` in the DDL and the invariant "ingest always stamps" is the guard (plus the migration).
3. **The prefix rule's removal is a behaviour change** for any reader who isn't the owner: on dev (one person) nothing changes; the `may_see` unit tests are replaced, not adapted.
4. **Lesson audiences stop equalling their topic's** when narrowed: tests from L1 that assert `lesson.access == topic.access` need the derived case; `sources::adopt_into_topic` keeps copying the topic's audience to sources (sources aren't derived).
5. **`UPDATE passage … WHERE document_id = $id`** on a 10 000-passage document holds the write lock for the statement; measured in L2-write's test with 5 000 rows on kv-mem (budget: ≤ 2 s); if slower, batched by `INSERT_MANY_MAX` through `update_passages` ids under the same lock.
6. **The dogfood agent goes blind after the deploy** (D2) until the owner widens its ceiling or publishes: the log sentence and owner Q4 cover it; nothing automatic widens an audience.
7. **`audit` writes under the write lock through a channel** (like traces): the writer task must flush before `Service::stop` returns (traces already do; audit joins the same shutdown), or a change's row could be lost on a crash — acceptable for traces, not for audit, hence the inline write on a full channel.
8. **Eval oracle and SQL agree by construction?** The oracle is the fixture's audiences × `groups::expand`, written by L2-evals; the SQL is L2-retrieve's. They are different code on purpose; if the oracle is wrong the gate fails loudly, never passes wrongly, because `owner_rank_identical` cross-checks the unfiltered replay.
9. **`Document.access` default change (`company` → `[]`)** touches the wire: apps from before L2 reading a document with an empty `access` show nothing different (they don't show audiences); `margin-mcp` ignores it. The `people.rs` migration test that expects `document.access == ["company"]` after `people-v1` is updated to expect the owning row's audience after `passages-access-v1`.
